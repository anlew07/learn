## 2. 对《同时穿越·末日模拟器》的适用设计

1. **把关键选择做成一眼看懂的“决策卡”**：现在的战技、策略、援助已经是正式规则，打开面板时可参考卡片的信息密度（图形、收益、费用、限制、适用情况），不改变其原引擎合同。
2. **把分身做成“角色档案”而不是统计表**：场景里可辨认的角色立绘/像素头像，与其成长、战技、今日工作及个人经历并列；不在主屏塞整页说明。
3. **让流派选择具有真实机会成本**：当前策略和构筑已有行动选择与资源影响，优先让“为什么这局适合救援/排险/成长”可读；先测已存在的能力差异，不立刻增加更多卡槽。
4. **事件要能留下长久回响**：触发、选择、之后的事件或结局应有联系；历史手记记录关键后果，不依赖长篇小说式连播文本。
5. **局外与局内要区分清楚**：开局选择、局内有限策略、结算/收藏各有自己的页面和可见结果，不把所有功能放到一个竖向长页。
6. **保证重玩价值来自局势变化，而不是抽卡概率和广告**：不同世界的事件、战技、资源与危机已有足够的设计空间，优先检验其策略分歧，再决定是否需要额外卡牌机制。

- **像素场景与角色品质：** 《贪婪地牢》手机版为第一参考、《Shattered Pixel Dungeon》为次参考；本项目不能因为卡包修仙的插画漂亮就突然变成纸牌/小说 UI。

- **角色成长与随机事件：** 《异世轮回录》+《卡包修仙》。

- **自动战斗表现：** 《血色虫灾》《Magic Survival》，未来“战斗地图观战”仍是 [候选设计](02-event-combat-view-modes-proposal.md)。

## 3. 先改表达，不先加抽卡系统

现有需求适合做的**轻量视觉验证**：

- 新手打开队伍/战技，能直接看到分身造型、装备/技能图形、简短属性与最重要的战略取舍。
- 战技候选采用可辨识图标/卡面，明确增益、限制和现有槽位，而不是仅列神秘名词。
- 重大事件只在必要时显示分支选择，并清楚说明资源代价与结果；不增加每天强制点卡片。
- 一局结束后能回看 2–3 个最有影响的真实经历，知道下一局有哪些不同路线值得尝试。

**本轮不实现**：盲抽卡包、抽卡付费、广告加速、额外货币、复杂永久抽卡仓库或对已有经济系统的未经批准重构。可后续做无规则改动的交互原型并通过玩家理解测试决定。

## 4. 未来验收问题

- 一眼能看出不同分身/战技/策略的区别吗？不展开长说明也知道为什么选吗？
- 玩家有没有真实机会成本，还是只选数值最大的那张？
- 随机事件和分身成长是否改变之后的局势，还是“一次性加减数值”？
- 结算是否把策略与经历联系起来，鼓励再次开局？
- 游戏主屏是否仍然以**世界场景**为主，而不是被卡牌与文案重新占满？
