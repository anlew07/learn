# 2AA · 分身自主行动演出与真实战斗受击反馈

> 基线：`main@5769ba7`（2Z 已合并并发布）。这是同一模拟器的场景表现增量，不新增独立战斗模式。

## 观察到的缺口

现有场景已经能按真实 `lastDecision` 将分身放在训练、采集、探索、排险和救援对应区域，也有 12.5fps 的 Canvas 装饰动画。但分身只有很小的左右摆动，五类行动看起来仍接近同一个待机动作；战斗回顾中的敌人只有闪光，缺少命中后的受击反应。像素视觉规范已把多朝向、逐帧动画和受击反馈列为后续差距。

## 本次实现

- 新增纯函数 `getWorldActionMotion`，将**最近已结算行动**映射为确定性的短动作循环：采集从补给箱右侧靠近并俯身、探索接近遗迹观察、真实战报存在时排险向敌群突进（没有战报只巡护）、救援从封印点左侧靠近、修炼原地聚气。
- 采集动作水平翻转现有原创分身精灵，使其面向已有补给箱；不新增角色贴图。
- 战斗突进与真实 `lastCombat.spectacle` 的 30 帧波次回顾对齐；只有战报击退比例覆盖的示意敌人会产生短促后退和受击闪光。
- 使用现有 requestAnimationFrame、Canvas 2D、12.5fps 限帧、暂停和系统减少动态效果设置。没有额外计时器、随机数、资源加载或依赖。
- 动作只是**最近结算行动的像素化演绎**，不是实时权威战斗，也不会推进日期、移动真实实体、追加掉落或改变存档。

## 技术选择

沿用浏览器原生 Canvas 2D 和项目已有精灵；本次不引入 PixiJS / Phaser / 动画框架。现有场景仅需少量 320px 逻辑坐标、整数像素位移和固定帧相位，第三方库会增加体积并与现有绘制器重叠。所有坐标由真实活动类型和固定帧计算，无 RNG。

## 验收

- Vitest：五类动作相位、往返路径、采集朝向、战斗命中门控、暂停冻结、帧循环确定性；真实战报受击回弹和零击退无命中反馈。
- Playwright：320×568、390×844、430×932；从正式引擎 RunState 构造最近已结算的五类动作，实际 Canvas 绘制并检查触控视口无溢出。
- 保持既有 2W / 2Y / 2Z 场景战报流程、存档、RNG、经济、策略和战斗数值不变。
- 尚未完成：多方向精灵、真正逐帧角色图、独立怪物 AI/实时碰撞、Android/iOS/TapTap WebView 真机验收，以及真人对动画辨识度的审美确认。
