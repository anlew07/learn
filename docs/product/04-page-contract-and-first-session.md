## 1. 一句话玩家任务与主循环

你是连接多个世界的守望者：**分身自己行动；你观察进展和危机，在关键时机调整长期策略、处理事件、安排跨界援助；最后看各世界是否在期限内满足救援条件。**

每次可见循环：**观察世界状态 → 发现机会/风险 → 做一次有代价的决定（或选择继续观察）→ 看真实状态变化与战报 → 调整下一步 → 结算/复盘**。

- **胜负真实规则**：救援准备达 100 只是必要条件之一；还取决于等级、物资、主线/威胁等该世界实际终局资格。危机达到 100、期限或其他真实失败条件也能结束世界。
- **首局数量**：第一局实际是双世界；“推荐新手”先聚焦显示灵灾，另一个世界仍运行；第三个兽潮世界属于后续局解锁阶段。**不得把首页“三个世界”的长期题材描述写成首局已经同时显示三个。**
- **长期反馈**：世界碎片、纪念收藏与称号已有记录功能；不代表已实现“花碎片强化属性”。
- **战斗边界**：已有自动三波战斗和战技选择；另开实时可操作的幸存者地图及“观战/快速演出/直接结算”仍是[候选提案](02-event-combat-view-modes-proposal.md)，不得放进已完成项或主线验收承诺。

## 3. 层级、入口与返回合同

### L0：首页（非战斗中的主游戏页）

- 唯一突出动作是**开始第一局 / 继续当前局**；其他为“完整开局、旅程档案、帮助、设置”等低权重入口。
- 首页帮助不用先创建存档；“重新开启”告知**放弃当前局、保留已结算的个人永久记录**（以实际存档规则验证），先确认后执行。
- 无档/存档损坏/只读/保存失败需要不同信息，不用无意义的“开始”掩盖存储故障。

### L1：主游戏固定 HUD（仅正在游玩的游戏场景）

- 固定且同屏可见：当前世界/切换、天数及运行状态、世界救援准备与危机、眼下最重要的目标、继续/暂停、一个当前情境主操作、二级菜单入口。
- **不可用整页纵向滑动寻找按钮**；场景是主体，不得恢复三世界卡＋日志＋所有控制纵向摞满的网页。首页与独立长帮助文档可依场景滚动；仅进行中的 L1 主游戏不可整页滚。
- 同时有多条事件时先显示**最紧急的一个入口及待处理数量**；必须能从二级层遍历剩余事件，不自动替玩家点击。
- 首局聚焦时仍要有“另一个世界仍在行动”的短提示及可直接查看全部世界的入口。

### L2：详细抽屉/独立二级页

- 世界详情、调度、队伍、战技、手记、帮助、设置均只有**一个明确功能主题**，允许内容区域内部滚动。
- 打开二级层不改变 RunState、随机数、支付、世界选择或日数；只有显式合法命令才能改变规则。抽屉本身不得偷偷暂停/恢复模拟，若特殊事件确需自动暂停，必须依真实已有规则显示状态。
- 关闭后返回**原世界、原视角和原滚动/焦点上下文**；屏幕返回、关闭按钮、Esc/设备后退等按当前平台能力合理处理。若在抽屉内提交合法命令，则应显示真实回执后返回，不复现旧数据。
- “不可用”必须说明原因（AP、材料、事件过期、只读、存档失败），不能只禁用而无解释。

### L3：阻断性确认 / 本局结算

- 只有放弃本局、会付资源的重大操作（依现有命令合同决定）、不可逆数据动作等适合确认；普通“查看详情/帮助”不弹确认。
- 模态层可见明确标题、影响、确认/取消，键盘焦点进入并能返回触发点；弹出和取消没有游戏经济副作用。
- 结算优先“结果＋主要原因＋下一局建议”，详细战报可点开而不是占满首屏。

## 4. 新手首局：按操作与触发点渐进展开

| 阶段 / 触发 | 玩家先看到 | 此时应会做 | 此时不主动灌输 | 可验证判据 |
| --- | --- | --- | --- | --- |
| 首开首页（无档） | 一句话身份、首局双世界说明、“推荐新手”主按钮 | 解释“分身自动行动，我决定方向”并开始 | 技能槽、历史图鉴、全部资源小项 | 未看文档能说清目的与如何开始 |
| 首次进入（默认暂停） | 选中世界、救援准备、危机、第一目标、继续模拟 | 按一次“继续模拟”，知道谁自动行动 | AP 冷却、全部策略比较、战斗随机公式 | 明白暂停状态，不以为游戏卡住 |
| 第 1–4 天 / 首次状态变化 | 昨日→今日准备/压力/行动变化，短反馈 | 观察并能说明至少一次变化来自分身 | 暂时不强迫玩家多世界援助 | 说得出发生了什么和下一步 |
| 第 5–8 天 / 首次可切换策略 | 一条“成长/救援/排险”倾向提示及机会成本 | 试一次合法长期策略切换，理解不是手动做一天行动 | 所有构筑组合 | 解释选择后损失了哪类机会 |
| 聚焦结束（当前实现第 9 天）或玩家主动展开 | 第二世界仍运行的明确提示、世界切换 | 指出风险更高的世界，能返回原世界 | 直接塞三世界全部长文 | 认出两个世界是同步演化的 |
| 首个合法重大事件（随机触发，不保证哪一天） | 发生什么、自动默认、到期、至少一项代价与预期 | 选择或明确允许自动处理，再看回执 | 所有历史事件 | 知道“不选择”也有后果 |
| 首次战技候选/首次战斗（不保证日期） | “自动战斗”标签、可选构筑、结果在先 | 选择一次合法战技；看战报实际收益或损失 | 实时手动走位、额外随机奖励 | 说清战技和经营/防线的关系 |
| 第一次可用援助 | 来源、目标、扣除与收益、冷却 | 看预览，确认或取消一次 | 默认展开全部援助公式 | 能讲出“救了谁、牺牲了谁的资源” |
| 本局结束 | 已救援世界数、逐世界因素、世界碎片、下一局建议 | 找到下一局，知道碎片目前不能加点 | 未实现的商店/深度解锁系统 | 不把“获得碎片”误以为可立即强化 |

这是**教学露出目标**，不是固定按天发新资源或强制改引擎事件。不同种子不保证出现首个战斗/事件/可用援助：自动化可以用合法状态注入验证界面，真人测试必须记录未触发而不能假报完成。教程提示可跳过、可重看，不阻挡必要点击；教学是否已看不改变引擎结局。

## 5. 帮助（S11）与设置（S12）的最小交付

### 帮助：首局就应可达，不用另造“百科系统”

**内容顺序**（每段首句须能在一屏内读完）：

1. **30 秒上手**：分身每日自主行动；观察准备/压力；继续、暂停、策略、事件、援助有什么不同。
2. **如何救回世界**：准备 100 不是立即通关，列出现实终局条件（以预览为准），危机或期限会导致失败。
3. **数值字典**：救援准备 P、危机压力 D、干预点 AP、分身等级 Lv、世界物资、灵魂与冷却；默认中文名优先，缩写只作补充。
4. **怎样做决定**：长期策略偏好 vs 重大事件一次性选择 vs 援助来源成本 vs 战技构筑；失败时为何按钮不可点。
5. **首局为什么只显示一个世界**：聚焦只是观看方式，另一世界没有暂停；如何切换查看。
6. **存档与异常**：本浏览器本地保存、关闭后通常暂停、自动保存失败怎么办、另一标签页只读怎么恢复；不承诺跨设备。
7. **重看教学 / 术语查询**：可随时从首页和游玩中的菜单打开，不需要清档重开。

**实现复用**：优先复用现有 PLAYER_GLOSSARY、getTutorialGuidance、已有生存手册与错误提示，避免第二套互相冲突的文案定义。#51 已有局内帮助抽屉，但**首页可达的帮助中心仍需单独验收**。

### 设置：低频偏好和信息，不替代游玩控制

**P0 最小版**：① 帮助/重新查看新手提示的入口；② 显示适配（文字标准/较大，若确实实现且能持久化）；③ 当前版本与“本浏览器存档、无云同步、另一标签只读”的说明；④ 返回游戏或首页的明确控件。设置入口应首页和局内可找，**不是在开局前才出现的“防线行动”实验开关**。

**P1 按需要补足**：减少动画优先尊重系统设置；新手偏好独立保存且可恢复；失败存档提示直达说明。真实数据导出/清理须有明确风险评估和方案，不自动批准。

**不显示**：未实现的音效/背景乐音量、语言切换、登录、云同步、付费、永久强化、清除所有数据。不要放“敬请期待”按钮伪装功能。模拟速度与长期策略留在对应游戏操作区。

## 6. 术语和文案合同（所有页面共用）

| 应对玩家说 | 不单独裸露为 | 文案含义与禁止误导 |
| --- | --- | --- |
| 救援准备 65 / 100 | P65 | 准备达到 100 **不等于**已救援 |
| 危机压力 70 / 100 | D70 | 达到阈值的后果依真实世界状态 |
| 可用干预点 2 | AP2 | 闭关预留不可用；具体援助支付依预览 |
| 分身自动行动中 | “AI 操作/引擎调度” | 玩家决定策略与关键事件，而非手动按天走路 |
| 主要倾向：训练成长 | “执行训练” | 策略是长期优先级，不保证每天只做训练 |
| 预计效果 / 实际效果 | “必定获得” | 预览说条件与概率；回执仅报告已经发生的差额 |
| 另一个世界仍在运行 | “隐藏世界不计算” | 仅隐藏显示，不改变本局同时模拟 |
| 本次救援结果 / 下一局建议 | “满 P 自动通关” | 不能编造确定的失败因果或永久加点 |

- 每个主操作**动词＋对象/结果**；禁用必有解释，成功回执数字来自同一次引擎结果。
- 信息优先级：**当前危机/决策 > 下一步 > 关键指标 > 可查细节**。单屏最多一个强调主操作；不要将全部日志、教学步骤、详细物资/技能表再次直接放在主场景。
- 像素 UI：低饱和统一色板、硬边和清楚图标；角色/物资/敌人要在手机尺寸可辨认；不用玻璃拟态、霓虹发光、科技控制台。字体可读性高于像素字体纯度。
- 参考成熟交互原则：[NN/g 渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)；模态可用性参考 [MDN dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog)，可优先使用原生语义实现，不要求迁移框架。

## 7. PR / 截图 / 真机验收的硬边界

**自动化可证明功能不坏，不能证明新玩家已经看懂。**所有实际验证填写在 [首次玩家验收基线](../qa/first-play-baseline-20261116.md)；具体真机记录见 [移动验收矩阵](../mobile-device-acceptance.md)。新 UI 合并前至少检查：

2. **可发现**：首页和运行中都能找到帮助/设置（若设置尚未实现，要明确标注缺口而不是提交空按钮）；首局可以解释“只见一世界”和“其余世界仍运行”；事件、队伍、调度、战报从新壳都可达。
3. **返回无副作用**：每种二级层打开/关闭后原世界及暂停状态不变；仅查看与重播不能多结算、消耗 AP/资源、前进日数或调用 RNG。
4. **关键回执**：真实世界压力/准备变化可看见；一次事件/援助/策略/构筑能找到后果，数值与引擎一致；失败时不隐瞒原因。
5. **安全**：存档失败停止推进/提供重试；只读标签不付款；刷新恢复不双写，重新开局确认与个人档案保留范围清晰。
6. **可读性**：至少 320–430px、44 CSS px 关键触控目标、中文字号放大、safe-area、减弱动画及键盘/关闭焦点。44px 是本项目触控设计目标，**不是 WCAG 2.2 AA 的硬性数字**；WCAG 2.2 的 2.5.8 默认最小为 24px 或满足例外，详见 [W3C](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)。
7. **联调与证据**：在最新 PR 头 SHA 核对 lint、format、text:check、Vitest、build、seeded balance 与 Playwright；截图、首次玩家原话、Android/iOS/TapTap WebView 是**不同证据层**。没有跑的明确写未验证，不以旧版测试绿灯替代新主屏测试。
