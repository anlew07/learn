# 核心玩法收口 RFC：从“观看模拟”转向“有目的地出击并改变世界”

> 日期：2026-11-17。审查基线：\`main@b9d28f097b23dd3775d78e82106b7bd96d09e223\`，审查时开放 PR 为 0。  
> 状态：**方案推荐 / 待产品审定；不是已上线功能，不自动授权大规模替换现有游戏**。  
> 配套：[灵灾 3–5 分钟最小原型规格](06-lingzai-sortie-prototype.md) · [后续开发分段与验收](07-core-loop-delivery-plan.md)。  
> 与旧 [产品总纲](00-game-product-blueprint.md)、[候选战斗观战方案](02-event-combat-view-modes-proposal.md)有方向差异时以本 RFC 明确标出的“拟议变更”为准，**不得默默把候选当已批准**。

## 1. 问题与决策

玩家实际反馈：打开后主要是选策略、推进模拟、看数值与战报；缺少即时操控、获奖后能消费的经营目标，以及再次打开/再次出击的动机。已有 HUD、弹窗、日夜反馈并不能补足核心玩法。

**推荐的新定位（待审定）**：**“可手动走位的短途幸存者式出击 + 自动战技 + 营地定向强化 + 每次出击后一次真实的多世界演化”**。不是把所有世界都改成纯动作游戏，也不是把旧三波统计动画改成看似可操作的假战斗。玩家主要决定“冒什么险、战场上如何生存、把资源投到哪里”，分身/另一世界继续有自身行动。

推荐先做一条隔离的灵灾垂直切片，不改正式 V0.2 默认主循环；验证是否能产生值得重复的行为后，再单独决定是否迁移主线。

**为什么不是仅做自动战斗观战**：观战能改善呈现，却无法从根本上解决“玩家自己做了什么”和“建造为何值得”两个反馈缺口。建议把现有 [02 候选](02-event-combat-view-modes-proposal.md) 保留作为战斗观战/跳过的后续可选模式，不误认已实现的实时战斗。

## 3. 30 秒内让玩家知道自己做什么

0–5 秒：选择**“灵灾试炼（试玩 3 分钟）”**，看见有分身、下一处目标“雾谷裂隙”，唯一主动作**“出击雾谷”**。现有正式局入口保留，不强行替换。

5–12 秒：进入全屏战场，底部左侧出现可拖动方向区，文案一句“拖动移动，战技自动攻击，活过 75 秒可带回灵石”。手指首次移动，人物立刻响应。

12–30 秒：妖影出现，角色自动放出基础灵刃，击中时有数字/击退反馈；敌人留下可吸附的灵石碎片，左上角战利品计数变化。玩家在 30 秒内至少完成“移动、看到攻击、收获一次物品”的有感动作（前提是按引导接近敌人；自动化使用确定性的种子验证）。

## 4. 3–5 分钟一条有因果的循环

\`\`\`text
营地选择出击目标
  → 75 秒生存战（玩家走位，武器自动攻击）
  → 中途一次战技二选一（冻结战斗时钟）
  → 撤离/生存结算（一次性发奖励）
  → 灵石投入「护灵剑台」Lv1（消耗真实资源）
  → 其它世界完成其当天自主行动，显示行动和风险变化
  → 再次出击，基础灵刃更强，击退同种敌人更快
  → 继续累积调查/封印准备与跨界援助条件
\`\`\`

**即时快乐**来自移动躲避、技能自动命中、拾取战利品、波次压力与新技能选择；**短期目标**是获得足够灵石建造；**长期目标**是用更高效的出击与分身发展守住世界，并在未来把取得的跨世界资源/记忆用于救援。第一原型不承诺玩家已经能在五分钟内完成整个世界封印。

## 5. 战斗、经营、多世界为何互相需要

1. **战斗 → 经营**：一次生存出击的结果决定带回灵石（存入当前灵灾 \`resource\`）；失败或主动撤离带回更少。领取只发生一次。
2. **经营 → 战斗**：把 6 灵石投入唯一的「护灵剑台」后，下一次出击基础灵刃每击伤害从 1 到 2。相同敌人通常少挨一击，战场可直接比较；代价是封印终局仍要灵石，不能无成本点满。
3. **出击 → 世界**：一次出击**替代**灵灾当天的一个主要行动；结算时所有世界通过同一次权威“日推进”执行自然变化、事件及其他世界的自主行动。不能一边出击一边让灵灾自动再打一场。
4. **世界 → 出击**：灵灾 D/持续威胁是后续遭遇强度输入（本切片使用少数清晰阈值），玩家离开战场后才得知世界风险怎样变化，不是仅刷新数字。其他世界可通过已存在的成长记忆或合法援助改变灵灾局势；第一轮至少可观察另一世界的**实际自主行动**，不得伪造每次必有援助奖励。
5. **跨世界的不可替代性**：当灵灾选择战斗与建筑、暂缓探索时，另一世界仍推进自身目标并可能产生跨界记忆；之后可用现有援助做跨世界取舍。若删去多世界，就失去“在一个世界冒险时，另一个世界自行作出选择并承担后果”的核心张力。**第一原型仅展示这种机制的可运行证据，不强塞第二世界战斗地图**。

## 6. 保留、调整、隐藏

- **保留**：独立世界随机流、P/D/等级/截止日、现有事件合同、主线/封印条件、战技 ID 与名称、灵灾角色/敌人素材、Canvas、单写存档/幂等规则、跨世界记忆/援助、UI 暂停事件的认知。
- **新增或调整（仅原型模式）**：玩家主动发起出击；移动与命中/受伤；一次战局中临时战技；可拾取战利品；一座有成本的建筑；出击对应一次世界日结算、暂停旧日钟；可复现的出击结果提交。
- **暂时隐藏但不删除**：长期策略主入口、旧三波文字战报的主要舞台、整局终局资格细节、手动闭关/所有跨界管理细节、多段事件文本。需要时通过现有详情可达，不能删掉底层规则。
- **本阶段不做**：三世界动作关卡、完整世界沙盒、复杂基地布局、法宝仓库、抽卡/广告/付费、开放大地图、Boss 全套、实时离线挂机、全局数值重平衡。

## 7. 重大方向风险与审定点

从“玩家管理策略与关键事件、分身自动作战”改为“玩家在灵灾战场手动移动”，是**核心定位变化**。尽管本次任务允许策划设计，**本文件只是推荐并发起评审，不代表用户已经同意将其全面替换到 main**。可选择只保留试验入口或继续纯观战路线。

风险：手操可能牺牲传统文字模拟玩家的轻负担；世界时钟不能再简单按 20 秒独立递进；原 \`step\` 没有指定当天行动的注入接口。解决方式：隔离原型、不覆盖存档、端到端验证先于默认入口替换；正式是否切换核心定位在最小切片验证后决策。
