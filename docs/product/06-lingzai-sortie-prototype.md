# 灵灾出击：3–5 分钟可玩闭环的执行规格（候选 V0.1）

> 类型：**第二阶段及其后续可直接开发的规则合同**，非当前已实装功能。基线 `main@b9d28f09`。  
> 产品总方向待审定，禁止直接修改正式双世界模拟的默认入口、经济/存档格式。  
> 配套：[审查与定位](05-core-loop-direction-and-audit.md) · [开发分段](07-core-loop-delivery-plan.md)。

## 0. 一次试玩成功的可见证据

目标：在 **180–300 秒**内（正常玩家操作目标，不是自动化保证值）完成：**第一场 75 秒出击 → 领取灵石 → 花灵石升级护灵剑台 → 第二场 75 秒出击 → 对比命中效率、获得真实的另世界日进展**。

建议节奏：进入与学习 10–20 秒；首战约 75 秒＋选择暂停 5–15 秒；结算/建设约 30 秒；第二战约 75 秒；观察世界变化/返回约 20 秒，合计约 215–235 秒。玩家停留在菜单的时间不计入战斗计时。

前置不用先读任何教程；进入场景后的**唯一主按钮**是“出击雾谷”。首次领取奖励后唯一突出操作切换为“升级护灵剑台”；建设后主按钮恢复“再次出击”。

## 1. 模式、输入与时间

| 项目 | 原型规则 / 不变量 |
| --- | --- |
| 进入 | 首页增加隔离的“灵灾出击试玩”入口（建议独立路径或明确的模式开关）；**现有正式模拟入口保持不动**。首次默认位于灵灾营地 |
| 状态 | 试玩仍从两个世界起局（灵灾可战场出击、废土只自主演化不做第二张地图）；禁止覆盖正式 `RunState/ProfileState` 的存档键 |
| 玩家操控 | 触屏左下可拖动方向区（半径 56 CSS px，手指偏移归一化，离开松开即停）；底层 Pointer Events + pointer capture，`touch-action:none` 仅应用战斗操控区；桌面提供 WASD/方向键 |
| 攻击 | **自动找最近敌人，玩家不能手动射击**；不要求摇杆加攻击双手操作，另一只手用于暂停/战技 |
| 时钟 | 只在战斗活跃且网页前台时推进 75 秒战斗时钟；升级选择/暂停/后台时冻结。**世界日不随每帧推进，也不调用旧 20 秒日钟** |
| 世界演化 | **一次出击成功、失败或主动撤离，只提交一次日结算**；在营地未出击时世界日暂停。其他世界仍在该次日结算中独立选择当天行动；不提供离线挂机 |
| 暂停 | 顶栏暂停/继续；`visibilitychange:hidden` 自动冻结，回来必须玩家继续；触控取消后角色停止 |

战斗地图单位为固定逻辑像素，不把每秒战斗时钟换算成旧“整日”。页面上的“昼夜进度条”在试玩模式显示**暂停的世界日**与“本次战斗剩余时间”，不伪装成世界一天正在持续流逝。

## 2. 战场空间、角色与敌人

- 单场地：**320×448 逻辑像素**、俯视开放雾谷战场，角色与敌人用已有 `src/assets/original/clone-cultivator.svg`、`rift-beast.svg` 为主要美术参考，不能从营地投影层伪造物理碰撞。首版无遮蔽寻路、无可拾取武器/可破坏场景；可以用固定地纹区分区域。
- 角色：出生在 (160,224)，最大生命 8，移动速度 95 逻辑像素/秒，碰到地图边界停下；接触敌人每次扣 1 生命，同一角色在受伤后 1 秒内无敌，受伤需有短闪烁与生命变化。
- 敌人 A「裂纹妖狼」：生命 2、移速 34，靠近角色并发生接触伤害。敌人 B「游离妖影」：生命 1、移速 48，靠近角色并接触伤害。首版直接朝角色移动，不使用寻路、势力 AI 或四叉树；敌人离开视野的出生点/状态需可重现。
- 三阶段：战斗时钟 0–25秒生成 6 只 A；25–50 秒生成 8 只 A/B 交替；50–75 秒生成 10 只 A/B 交替，总量 24。每阶段在对应时间段均匀出生，不能一次全部堆在角色脸上；距角色至少 80 像素，出生位置取**独立战斗 seed**。同时活跃敌人上限 24，超出生成排队但不丢计数。
- 世界强度映射：`D<40` 为标准上述数量；`40≤D<75` 最后一阶段 +2 A；`D≥75` 最后一阶段 +4 A。**只在出击入口快照中读取 D**，战斗中不让别的世界帧逻辑偷偷改敌人；UI 进入时显示明确的“雾谷危险等级”。
- 主动清空敌人不是即时获胜：到 75 秒且生命 >0 为“维持结界成功”，未消灭的敌人撤散；生命为 0 立即战败/撤离。玩家可点“立即撤离”，有确认防误触。无首领、无多图地图、不追求全清。

## 3. 攻击、战技、打击反馈

- 初始基础攻击「灵刃」：每 **0.70 秒**向半径 128 内最近的敌人发出一枚飞行灵刃，基础伤害 **1**；弹速 220 像素/秒、命中消失，目标离开射程时不远程追踪。无目标不发射；小范围圆形命中框，先撞到谁先结算。
- 第一阶段结束（战斗第 25 秒）**自动暂停并给一次临时战技二选一**，示例：`thunder`「驭雷符」每 4 秒对最多 2 个临近敌人各造成 1 伤害；`rune`「聚灵阵纹」每 10 秒抵挡下一次接触伤害 1 点。选择后恢复；“跳过/默认”按钮明确执行默认选项并留回执。候选不会因为 `Math.random` 每次乱变。
- 复用 `POWERS.lingzai` 中的稳定 ID、中文名称和标签；新增实时发射频率、命中数值必须在 **原型配置**明确声明，**不可将旧 `computeWaveBonuses` 的 0.5 XP/0.25 物资加成当成逐帧命中效果**。
- **重要：战场战技仅作用本场**，存在 `sortieBuild` 临时状态，**不写现有 `world.build.pending` 或永久装备槽**，避免与旧 Lv2/P65 战技获取合同冲突。长期变化由营地建设担当。
- 命中反馈：敌人闪白/轻击退（仅演出）、生命扣减数字、击倒后清楚的灵石碎片标记；禁止用战报演出时随机决定实际伤害。技能升级卡需显示真实数值和倾向，不可假特效。

## 4. 掉落、结果、唯一发奖

- 敌人按**本次累计有效击倒数**每达到 3 的整数倍，生成 **1 个“灵石碎片”**在被击倒位置；拾取范围为角色 28 逻辑像素，拾到时播放短吸附效果。只计算拾到的碎片，未拾取的不带出。
- 每 **3 个已拾取碎片**折算成 **1 灵石**，最多折算 2 灵石/场；多余碎片没有跨场货币价值。显示“已拾碎片 X / 可换灵石 Y”，避免模糊币种。
- 生存 75 秒：**基础 +3 灵石**，另加已拾碎片可兑换灵石（0–2）；获得 **成长经验 +2**、灵灾拯救准备 **P+2**，不额外发世界碎片。**生命 0 或主动撤离**：基础奖励、P 与经验均为 0，仅保留可兑换灵石（0–2），仍消耗这一日的行动机会并推进世界环境。
- 出击奖励结算在**唯一权威原子指令**中发生一次，和世界日同步；不经过旧 `doAction('fight')` 的奖励/ `waveCombatBonus`，不重复触发经验、材料或战潮加成。结果 UI 只能从真实已提交的 receipt 读取差额。
- 结算屏最少显示：本次击倒数、战场存活秒数、带回灵石、XP、P/D 实际前后差、另一世界的实际自主行动摘要；提供“返回营地”，不加入爆箱/抽卡。

### 第一场示例（**推演样例，不是实测**）

初始灵灾灵石 4；击倒 15 敌、拾取 6 碎片、生存成功 ⇒ 基础 3 + 碎片兑换 2 = **带回 5 灵石**；灵石变为 **9**（若无其他合法资源事件）。花费 **6** 灵石建设后剩 **3**；第二场基础灵刃伤害由 1 变 2，妖狼从需命中两次变一次。若第一场只拿基础奖则 4+3=7，仍可建造一次。真实 `D` 在出击日由世界压力与排险回执共同决定，不用预先写死 D 一定下降。

## 5. 第一项建设：护灵剑台（唯一建造对象）

| 规则 | 定义 |
| --- | --- |
| 显示 | 营地保留已有地形，只增加一处可点的「护灵剑台」状态位；没有建设前为灰色基座 |
| 条件 | 原型模式、已完成至少一次出击、灵灾仍在运行、未建设、当前灵石 ≥6；不要求 Lv2、AP 或第二币种 |
| 操作 | “投入 6 灵石，修复护灵剑台”；按钮先预览剩余灵石及“会占用未来封印物资” |
| 结果 | `camp.forgeLevel = 1`，支付灵石 6，后续出击「灵刃」伤害 1→2，营地图层由残破变为亮起；只允许建一次 |
| 取舍 | 成长与更快清怪可提升后续收益，但灵石也是灵灾终局封印所需资源；不允许免费拆除返还 |
| 防重复 | 多次点击、重放 operationId、不足 6 灵石、非营地/只读/存档失败均不得重复扣款或升级 |

仅此一座设施；暂不添加工人、建筑队列、科技树、升级素材合成等系统。

## 6. 世界日与跨世界同步：必须避免双行动

正式引擎现状：`Engine.step(state)` 会自动调用每个世界的 `chooseAction→doAction`，然后自然恶化/事件/记忆/终局判断。**不能**先手动发一次战利品再直接调用原样 `step`，否则灵灾会同一天又自动行动一次。

候选接口合同（**供第二阶段实现，不是现有 API**）：

```text
startSortie(seed, state) -> 只创建战场临时状态（不推进世界日）
advanceSortie(frameInputs, fixedTick) -> 只更新战场状态
finishSortie(sortieId, outcome) -> 形成结果候选，不立即写世界资源
applyCommand({ type:'sortie-settle', operationId, args:[sortieId, outcome] })
  -> 检查模式/阶段/seed/时长/掉落合法性和重复领取
  -> 用【一次】灵灾主要行动替换当日自治行动，结算奖励
  -> 同【一次】世界日步骤结算灵灾和废土的环境、事件、记忆/回响
  -> 批量存 Run/Profile/原型状态，返回权威差额回执
```

设计约束：受信任的战斗结算结果来自**同一个确定性战场状态与动作序列**；不要把客户端上报的裸数值当成可随意伪造的奖励指令。无服务器原型先保证本地可信状态、回放校验和重复提交防护，不声称防作弊。

- 世界 `day` 每结算一次仅 +1，仍保留各世界独立 RNG；同一轮的废土行动在权威引擎逻辑中真正发生。
- 只允许一个 active sortie；出击时营地不能另外点击加速/推进；现有日进度 UI 必须明确区分战斗计时与世界时间。
- 本次灵灾行动类型记录为 `sortie`，计入当日唯一主要行动，并与“自动清剿”一样承担失去训练/探索日的机会成本。
- 第一轮跨界只要求：返回营地能看到废土实际 `lastDecision`/P/D/材料差额（不是写死“废土支援 +X”）；原有记忆、援助合同照常运行，满足真实条件才给收益，**不为了演示保证出现而假发记忆**。第二世界无需战斗场景。
- 如战斗后 `D≥100` 或到达截止日，按已有引擎判断失败；不能用“出击成功”覆盖“世界已失守”的真实结果。

## 7. 存档、边界态与回退

- 原型为**独立命名空间/独立模式**；不直接覆盖 `simultaneous-apocalypse-simulator-v1` 和 Profile 键。只在独立试验档写原型状态；旧数据保持可恢复。
- 写入必须遵守现有 `createSaveRepository`、Web Locks 单写、`operationResults` 幂等思路；扩展时单独考虑 `RunState` 验证与版本迁移，不把新的 `camp` 必填字段塞给旧存档。
- 战斗前存“准备出击”的已提交快照；战斗中临时态不发永久奖。隐藏标签只暂停，继续仍是同场；**浏览器刷新/崩溃**首版回到出击前营地，不发奖、不推进日（牺牲本次临时拾取），允许再次出击；需要给用户看得见的恢复说明。
- 双提交按 `sortieId` + operationId 做**两层幂等**；相同 sortieId 换 operationId 也不能再结算。发奖已提交但 UI 没来得及展示，重新加载仍能读取权威 receipt；不得再次提交。
- 战斗 0HP 与主动撤离视作正式结束、推进一次日；“刷新未提交”与“主动撤离”不能混为一谈。
- 只读标签不能开始战斗或写入结果；保存失败时冻结游戏并显示重试，不允许先发奖后默默忽略失败。
- 试玩完成可以返回原模拟器，不做全局存档清空、数据导入/导出或正式存档迁移。

## 8. 明确验收用例

1. 首次进入：单一主操作 5 秒内可见；30 秒内在 320×568 和 390×844 能移动、见自动命中与掉落；横屏/键盘最少功能不崩溃。
2. 手动控制：pointerdown/drag/up/cancel、松手停、斜向速度归一化、界外不穿墙、暂停不位移；按压 UI 按钮不能误触摇杆。
3. 战斗：固定 seed/输入时间线结果相同；战场刷新率 30/60/120Hz 对相同时长不改变逻辑命中/出生数量；隐藏页不偷偷快进。
4. 玩法：75 秒生存成功、0HP 失败、主动撤离、25秒技能选择；两种战技可观察到不同实际效果。
5. 收益：未拾取不计数、每三碎片换 1、最高 2、本场奖励一次；成功基础 3，失败无基础；不得叠加旧三波收益。
6. 建设：初始 4 灵石不能建，首场生存后至少可付 6；支付后第二场妖狼命中次数降低；刷新/重复点击不复发。
7. 演化：每次结算灵灾恰好一个主要行动、废土恰好一个自主行动，`day+1`；其他世界的 RNG/行为与相同 seed 的兼容对照一致；真实 pendingEvent 在营地可处理而不穿透到战斗时钟。
8. 存档：运行中后台暂停、刷新回退、已发奖刷新可回执、存档拒绝写入安全冻结、两个标签只有单写者；原正式档字节不变。
9. 终局：高危失败不被战斗结果掩盖；P100、Lv3、封印资源要求原样保留，未在本原型模拟完整通关。

> 上述数值是**实验初值**。第二阶段须用固定脚本检验首场生存率、能建造比例、第二场击倒效率和是否出现无意义无敌/刷资源；更改参数先记录同种子前后对照，不宣称未经真人验证的“玩家胜率”。
