# 2AG-I：正式险地回收的移动端触控验收

## 背景

2AG-H 已把回收任务、撤离兑现和紧凑 HUD 接入正式灵灾遭遇。现有浏览器测试覆盖任务选择和 320×568 布局，但此前摇杆回归主要使用鼠标事件，尚未证明触控指针真的驱动走位，也未从正式页面完整走通「移动到回收点 → 完成目标 → 主动撤离 → +2 灵石」。

## 本轮范围

只补充 Playwright 移动端验收，不改运行时战斗规则、奖励、存档或 UI。

- 使用 Chromium CDP `Input.dispatchTouchEvent` 发送触控开始、移动和结束事件。
- 明确断言浏览器收到的 `pointerType === "touch"`，不以鼠标拖动冒充触控。
- 不调用自动滚动；检查页面滚动位置保持为零。
- 在 320×568、390×844、430×932 检查险地回收任务条完全位于视口内。
- 在 390×844 使用真实坐标触控摇杆接近回收点，等待权威模拟完成守卫驻留，再通过正式撤离按钮结束遭遇。
- 当前固定场景从出生点 (160,224) 朝回收点 (258,92) 进行约 1.85 秒的归一化斜向触控，验证真实移动轨迹而不是直接改写战斗坐标。
- 检查正式回执包含 `missionId=salvage`、`objectiveStatus=completed`、`objectiveStones=2`，且正式日期只推进一天、fight 只结算一次。

## 验收边界

Chromium CDP 触控属于自动化设备模拟，能验证网页触控事件链和布局，不等同于 Android Chrome、iOS Safari 或 TapTap WebView 真机验收。真实设备仍需检查摇杆手感、系统手势冲突、不同屏幕安全区和长时间运行稳定性。

本轮不调整回收点位置、守卫数量、驻留时长、敌人强度或奖励数值；如果触控路线表现出过高失败率，应先收集真实设备样本，再单变量调整规则。
