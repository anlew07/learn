# 灵灾出击 2L：两场内出现真实的任务风险与营地资源选择

> 日期：2026-11-18。**隔离候选玩法的工作合同，非已批准正式规则。** 父集成 PR [#74](https://github.com/anlew07/learn/pull/74) 2K 完成 HEAD `8f3c75d45b17c0fcfbcf3995ac8b31944709c46f`，整合 [CI #44257392976](https://github.com/anlew07/learn/actions/runs/44257392976) success（353 Vitest / 106 Playwright）。参考 2K-A/B/C 报告和《完美国度》公开经营—军事资源循环。**此阶段从参数实验改为可玩的 3–5 分钟纵向切片。**

## 一、事实、失败经验与设计原则

现有：
- 75 秒出击、25 秒暂停选技，击退 3 敌掉 1 碎片，28px 拾取，3 碎片兑 1 灵石最多 2，获胜基础 3 灵石，最高 5 石。
- `src/engine.js` 两世界开局各有 **4** 单位资源，灵灾首战胜利最低再得 3；2K-C 的 720 配对样本中 **718** 组首战后就够付 6 灵石修剑台，而非预想的普遍需要攒钱。不能凭 UI 文案说玩家正在攒 6 石。
- 同批不投资次场 **719/720** 获胜，2I/2J/2K 已验证单纯攻速/伤害/+2 HP 与灵石回报的联动很弱；第六场剑台仍 0 组回本。曾尝试隐藏 96px 附近敌人拾取条件来分配 1 石保底：没有新增风险，仅扣减收入，已拒绝。
- 2J-D 已解决部分反馈表达，但目前战斗缺少**玩家显式接取的可选任务**，新手即使打赢也没有明确风险收益选择。
- 不缩小 28px 普通碎片拾取容差，不为增加风险凭空直接扣血，不用新增强制重复点击/离线等待来营造经营。TapTap H5、原生 JS/Canvas2D 保持。

参考设计原则（只借思想）：
- [《完美国度》](https://www.taptap.cn/app/734014)公开的采集、建设、生产、军队、讨伐之间双向发展；不要照搬具体建筑、兵种、UI、文本、资源比例。
- [Deep Rock Galactic 官方 Wiki：任务结构](https://deeprockgalactic.wiki.gg/wiki/Missions) 提供主目标 + 自愿接受的奖励任务思路，奖励应让风险/路线选择有意义；绝不直接复制其矿物/洞穴/多人玩法。

## 二、本轮必须交付的 **可玩结果**（不是再写纯分析）

在新的隔离试玩路径中，玩家实际完成：
1. **营地选择任务**：界面有两种可理解的意图：**稳妥巡护**（原 75s 生存和原收益、允许自由拾碎片）或 **险地回收**（可选额外奖励与明确可见的额外战斗风险/位置目标），不默认替玩家接高风险任务。开局 4 灵石仍原样显示。
2. **真实战场目标**：若选择回收，战场在指定时段展示**可见且能移动过去实际接触的实体回收点**和完成状态；战斗目标必须是真正的 `stepSortie` 固定 tick 状态，而非 UI 装饰。允许手机容错。若目标由敌人守护，额外敌人/弹道必须从真实模拟器产生，与因果上可衡量的受击相关；绝对不写“捡到就扣血”。普通技能与拾碎片规则不能失效。
3. **透明且权威的奖励**：基础获胜 3 石、普通碎片至多 2 石保持不变；险地回收任务若**真实达成且完成本场**才获得一个单列 `objectiveStones` 的**候选**额外收益（第一版可测 +2 石，意味着**仅达成任务才可能超过原有 5 石上限**）。未达成不减少既有保底/碎片收入；失败/撤离领取规则必须在选择时说清楚（第一版候选：只在最终获胜时发任务奖金）。是否批准 +2 必须由权威配对及实测风险决定，而不是从 UI 手改 stones。
4. **回营投资选择**：首场结算 7–9 石就几乎立即买得起现有 6 石剑台，所以“储蓄到 6”不是有效默认对立面。第二场开始前让玩家在**保留资金**、**原 6 石永久剑台（保留当前实际效果）**与**最多一个与险地任务有关的一次性准备候选**之间权衡；小额准备第一版以**任务回收更安全/更高完成率**为目标，不能再简单 +2 HP。准备必须有成本、只消耗一次、真实改变任务结果，且与两技能的战略价值有差异。成本与增益均待试验，**不是正式授权数值**。
5. **第二次出击**：能看到已付费的准备是否生效，是否成功回收，任务失败为何没有奖金，以及净灵石与两世界日结算。若实际回本/风险不成立，拒绝候选；不可仅凭“多一种按钮”接受。
6. **回放/存档保护**：任务、购买与准备都必须写入独立出击档中的持久选择/消费状态，权威 `Engine.settleSortie` 必须用该状态重放场景；不可接受在 `src/sortie.js` 事后替换回执或玩家直接伪造奖金。旧版无任务字段档案按原稳妥巡护恢复；正式 Run/Profile 不变。

## 三、两条玩法候选要分清，不宜混成一个实验

| 选项 | 玩家承诺 | 实际危险 | 成长/资源 | 不应出现 |
|---|---|---|---|---|
| 稳妥巡护（原基线） | 撑满 75s，可按现规则回收普通碎片 | 既有波次 | 3 石存活保底 + 最多 2 石碎片 | 偷改起始 4 石、暗减保底 |
| 险地回收（新实验） | 额外前往可见回收点，守护挑战在地图中实际发生 | 只有接此任务才增加守卫/暴露机会；风险需真实碰撞与玩家路线证明 | **候选**额外 +2 石，独立权威回执项目；未完成保持原保底 | 隐藏敌距条件、接任务直接扣血、无目标就白领 2 石 |
| 暂不投资 | 保留本次实际赚到的灵石 | 无额外战前效果 | 留足后续世界救援的资源储备 | 因没花钱而取消原有奖励 |
| 永久剑台 | 真实付 6 石修复，仅一次 | 既有规则伤害 1→2 | 若仍无资源回报须明确告诉玩家 | 未付钱直接标记 forgeLevel=1 |
| 一次性准备（只研究一个） | 实际付费且下一场有可见效果 | 改变险地任务的可接近性/容错，而不是随手加生命条 | 对高危任务或误操作应有可测价值，成本含在 ROI | 无法回放的前端补血、重复扣费、无条件自动补资源 |

上面所有新内容只可在隔离 PR 中实施，**验收前不得并入 #74，更不许合并到 #70/main**。

## 四、模块与跨线接口合同（不得三个分支一起改引擎）

- **2L-A·战斗任务**拥有 `src/systems/sortie-sim.js` 的目标实体/守卫、`src/systems/sortie-rewards.js` 的分列任务奖金、`src/systems/sortie-trace.js` 的权威移动轨迹重放适配，以及**只允许**修改 `src/engine.js` 中与任务验证直接相关的结算局部函数。config 的目标配置归 A，原常规奖励/技能常量不变。A **不得修改** `src/systems/sortie-session.js`、`src/sortie.js` 或 CSS。
- **2L-B·营地经营/选择/界面**拥有 `src/systems/sortie-session.js` 中出击选择和一次性消费、`src/sortie.js`/ `src/sortie.css` 中的任务选择和出击结果表达、文字审查清单。B **不得直接修改** A 的 sim/rewards/trace/`engine.js`；优先在隔离影子引擎验证 B 的费用/幂等，再对接 A 的真实任务状态。若 A 接口仍未稳定，**不要提交无法独立验证的生产 UI 按钮**。
- **2L-C·质量验收**只新增专属 Playwright、定种子回归、QA 文档与人工可玩性检查记录，不修改 A/B 的生产代码；测试初期可针对现有 2K 基线编写，待 A+B 对齐再覆盖真实新任务、第二场、刷新隔离与移动控制。
- **接口约定（草案，A/B 需在 PR 中确认）**：本次选定 `missionId` 限定 `safe`/`salvage`；隔离档 `run.sortieCamp` 增加可选带日/操作 ID 的任务/准备回执，`prepareSortieArchive` 返回本场任务和准备状态，战斗 create/replay 使用同一传入值。临时缺省字段表示 `safe`，**不可把 missionId 当作任由前端传入的结算奖金指令**。消费、幂等、回放必须与 `sortieId`/日/单次准备绑定且旧档可兼容。新字段确切命名/签名由 A+B 在独立 PR 中冻结；不要分别编出两个不兼容的数据模型。
- 如果需要同时修改以上跨线边界、改结算 hash/奖励、更新正式档结构，由总控在**另一个隔离集成提交**统一调整并执行联合测试，不允许在各线擅自重构或覆盖别人提交。

## 五、门禁：必须对比真实行为，不能只比数字

测试矩阵最低 **40 seeds × D0/40/75 × 雷/纹 × 稳妥路线 / 主动任务路线 / 主动误操作（短反向、方向偏移至少一种）**，每个任务用 **同条件配对**，至少覆盖首场、次场真实选择和结算。记录分组分母（任务选取/可实际执行/达成/未达成/失败/撤离/可继续下一场），首次看到目标与第一次领取时间、敌群接近/守卫伤害、**实际受击**和余命、击退、普通碎片、**可额外兑换的任务石**、实际日结算资源与废土变化。

特别判断：
- 与稳妥巡护相比，险地回收应在至少一个中/高危险或误操作组出现**实质可观察的挑战**，而非同路无新增风险就白得额外收入；需提供资源收益与生存代价的配对表。D0 不需刻意制造失望感，D75 不允许强行必死。
- 对于一项真实付费准备，第二场任务净收益、损伤/胜负、完成率和至少延伸到六场的资源累计需一起看；如果只抬高 HP +2 但所有人照样赢，不通过。
- **三种手机视口：320×568、390×844、430×932**。营地任务是玩家主动选择、角色接近回收点、战技选择时固定暂停、结算显示奖金与资源来源、剑台/准备付款、再次出击都可以用真实坐标直接触摸。测试时不以 Playwright 自动滚动掩盖控件越界。
- **存档与回放门禁**：没完成的出击刷新不得领奖/扣重复费用；相同出击 ID/操作 ID 幂等；不同 ID 重放不能重复买；非法任务 ID/非法状态需拒绝；与正式档隔离；既有 2K/2J 单测、文本审核、固定种子、构建、Actions 均过。
- 连续 2K 失败以后，任何新候选若不能形成具体玩家可见的意义，应**明确否决，而非无限扫描参数**。首批范围不涉及正式线上迁移和发布。
