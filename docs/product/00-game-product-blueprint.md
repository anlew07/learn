## 0. 本次审计结论

现有文档主要围绕规则、技术和单项决策（如 docs/05-ui.md、docs/09-player-journey.md、docs/08-decisions.md、docs/14-pixel-ui-closure.md），缺少贯穿整个产品的**功能地图、界面责任边界、基础设施菜单、玩家路径和验收指标**。

对 main 源码的核对结论：

- 已有：首页、快速开局、单世界起步并随成功救援扩展为最多三个并行世界、暂停/继续、1×/2×/4×速度、世界详情、自主策略、重大事件、援助/融合、战技构筑与战报、结算、日志/统计、彩蛋和跨局纪念收藏，以及 IndexedDB 存档和 Web Locks 单写保护。
- 首页有「进阶设置 · 防线行动」开关，但**这不是完整的独立设置页**；也未确认有可供玩家随时访问的帮助/术语辞典、数据管理页、音频设置。
- 世界碎片与永久发现有记录，但**没有证据证明已经实装消耗碎片的永久属性升级商店**，不得在菜单或结算中暗示「已经可以强化」。
- 首局快速开局仍会聚焦一个世界、其他世界同时推进；初始暂停需明确引导。这两点已由 #45 改进界面提示、#48 接入玩法指导及 QA 回归；**是否已被真正的新玩家理解仍缺少人工试玩证据**。

**总体设计结论**：本游戏需要的是「自动发展的末日局势 + 玩家在关键时刻做有限但有意义的决策」，不是无休止的每日手动点按钮，也不是纯文字监控仪表盘。优先把玩家角色、目标、行动与反馈说清楚，再考虑增加内容和系统。

## 1. 产品定位与目标玩家

### 1.1 一句话概念

**你是一名能感知多个世界的守望者。分身在各自的灾变世界自主求生；你负责判断危机、调整长期策略、调配有限资源，在无法兼顾一切的情况下尽力救回更多世界。**

### 1.2 产品承诺

1. **可看懂**：不读开发文档，玩家也能说出目标、风险和可操作项目。
2. **有选择**：调整策略、事件决策、援助和构筑有真实机会成本；不以纯运气或盲点数值作为核心。
3. **有回报**：每次主动选择有因果回执；成功或失败后知道发生了什么、下一局能尝试什么。
4. **有氛围**：像素生存营地、不同世界的故事与生存压力，不是蓝光科幻终端。
5. **可随时离开**：H5 手机前台游玩、暂停与恢复可靠；默认没有真实时间离线收益。

### 1.3 目标体验 / 非目标

- 目标玩家：喜欢短时经营决策、局内养成、随机事件、自动战斗构筑的手机玩家；可接受观察分身自动行动，但希望关键时刻有掌控感。
- 目标平台：TapTap H5 手机版，优先竖屏、触控、低资源占用；无需账号才能开始当前单机版本。
- 非目标：实时摇杆与碰撞弹幕、重度在线多人、公会、广告商业化体系、复杂跨设备云存档，或「P 增速无限翻倍」的纯挂机数值游戏。
- 游戏暂不确定是否加入增量系统。**增量玩法是备选设计实验，而不是排期需求。**
- 世界观采用开放式灾变谜团，**不预设唯一幕后反派或唯一终极真相**。

## 3. 完整玩家生命周期

### 3.1 一局的路径

1. **首次进入**：看到「我是谁」「目标」「如何开始」，不需要先读十屏设定。
2. **新游戏准备**：选择简洁/完整查看方式；三波战潮如仍为试验模式，应明确说明；非首局不误导显示可玩三世界数量。
3. **开局**：游戏默认暂停可见；醒目提示「点击继续模拟」与「分身会自动行动」。
4. **自动发展**：世界推进，展示当前最重要的局势、各世界状况和为什么做了某行动。
5. **第一次介入**：一个真实重大事件/策略选择，展示费用、可预期结果、超时默认和操作后的回执。
6. **战斗与构筑**：在合适节点选择或自动选择战技，展示胜负、收益与对世界局势的贡献。
7. **跨世界联动**：在玩家理解两个世界后开放援助/融合的完整决策，清楚显示来源、目标、费用和牺牲。
8. **终局准备**：救援准备达标与最终资格是两件事；对缺少的等级、资源、战力和事件标记分项展示。
9. **结算**：显示成功/失败、主要原因、玩家关键决定与下一局学习方向。
10. **局外回看与再开**：查看本局日志和永久收藏，再进入下一局；不暗示尚不存在的升级系统。

### 3.2 玩家责任与系统责任

| 系统自动做 | 玩家主动决定 | 页面需要解释 |
| --- | --- | --- |
| 分身每世界每天一个主要行动 | 选长期策略、暂停/速度 | 世界每天会自己推进，玩家不是逐日指挥官 |
| 世界危机增加、普通结果自动处理 | 处理重大事件、适时干预 | 危险、费用、自动后果、最后时限 |
| 条件满足时进入原有战斗 | 选择战技/援助/融合 | 战斗如何影响成长与世界压力 |
| 可结算时依规则完成世界结果 | 局外继续、查看记录、开新局 | P100 不是直接通关、失败主因是什么 |

任何新增功能必须说明它属于哪一列，否则会重演「谁在玩游戏」不清楚的问题。

## 4. 信息架构：少导航、明确分区

### 4.1 建议移动导航与进入关系

- **首页 / 启动层（非底栏）**：继续游戏、开始新局、局外档案、设置、玩法帮助。
- **新版游玩 HUD（#51 基础已集成，A/B 联合扩展见 #58）**：主屏固定展示状态、选中世界像素场景、危机/救援进度及暂停/策略等常用操作；**调度、队伍、手记、帮助、设置**通过抽屉或独立页面进入，不再整页上滑查找操作。详见 [固定主屏规范](01-fixed-game-screen-redesign.md)。#45 旧四栏是可返回的详细视图，不是最终默认界面。
- **顶层工具入口**：暂停/恢复、倍速放在营地固定工具区；**设置/帮助**用页头或「更多」可达，不挤成第五个常驻玩法标签。
- **上下文页面**：重大事件、战斗选择、跨世界援助、最终资格、结算从相关页面进入，完成后原位返回。
- **异常态**：存档失败、只读标签页、无法开始新局等要有不误导的独立警示，不被导航遮住。

A 线 #45 已交付阶段性「营地、调度、队伍、手记」长页，B 线解释模型已通过 #48 接入；自动化移动视口和流程测试已验证。但**用户实际试玩明确否定了纵向长页的手机游戏感**，已进入新一轮固定 HUD 重构需求；真实设备和新手理解仍需人工确认。

### 4.2 首屏信息预算

在 375×812 类竖屏设备打开正在进行的一局，首屏的优先顺序应当是：

1. **本局目标与当前天数**（一句主目标 + 数字）：今天为什么值得继续。
2. **最紧急的一件事**（若存在）：哪个世界、为什么、可以怎样介入。
3. **像素世界观察场景**：选中世界分身的自主行动、地点与危险演化占据主视觉；其他世界用常驻按钮切换，不要求长页滚动。
4. **固定模拟控制与关键状态**：明显的「继续/暂停」+ 速度、准备/危机/期限 HUD；策略、援助、战技从固定操作区/菜单打开。
5. 其他信息（构筑、长日志、复杂统计）进入次级层。

一屏里同时出现多个高亮按钮时，必须能解释主次；颜色不能成为唯一风险提示。不能为了实现「一屏装下所有内容」把字号或点击区域挤小。

| S15 隐私/版本/反馈 | 发布必备信息 | 版本、更新概要、数据在本机的说明、适用隐私信息、反馈渠道 | 审核文档已备；玩家可达页面需核实 | P1 |
| S16 音频、成就、深度收藏 | 内容增强 | 只在真实内容与系统存在后启用 | 候选，不属于当前交付门槛 | P2 |

**页面不等于 16 个独立底栏标签。** 其中 S05/S14 可能是覆盖层，S11/S12/S15 归「更多」，S13 是首页或手记子页。具体 IA 可以调整，但**职责不能消失**。

## 6. 各页面交互规格与验收

### 6.1 首页（S01/S02）

**结构**：游戏标题与简短定位 → 「继续」/「开始」唯一主按钮 → 简短的本局机制说明 → 非主操作：局外档案、设置、帮助 → 版本与存档提示。

- 无存档：主按钮「开始第一局」；清楚解释首局先有两个世界，后续逐步解锁更多内容；不要一边宣称同时控制三世界一边默认隐藏第二世界而不解释。
- 有存档：主按钮「继续第 N 天」，副按钮「新开一局（将覆盖当前局）」；任何覆盖先展示影响范围及确认。
- 首次快速体验：明确「聚焦查看灵灾，其他世界仍在自动发展」；提供随时展开全局的入口。
- 说明全部使用真实状态；未启用的能力显示为介绍或不展示，不做假按钮。
- **验收**：未看说明的玩家在 60 秒内能指出「这是自动生存模拟」「玩家主要作策略干预」「从哪里开始」。60 秒是体验测试目标，不是已达成事实。

### 6.2 营地（S03）

**结构**：目标与天数 → 一项高优先危机/待处理事件 → 多世界摘要 → 继续/暂停和速度 → 最新有意义结果。

- 无待办时显示「分身正在自主行动 / 可以观察或调整策略」，而非制造虚假的按钮。
- 4×新重大事件按既有规则暂停；其原因与恢复入口必须清楚。
- 临界风险有文字+符号+色彩，拒绝只用红绿区分。
- **验收**：玩家知道模拟是否暂停、下一步应去哪里，不需要盯日志寻找控件。

### 6.3 世界详情（S04）

每个世界遵循统一布局：世界情境与人物 → 危机压力（越高越危险）/救援准备（越高越接近目标） → 资源与等级 → 当前自主策略及其解释 → 合法事件/救援入口 → 完整终局资格（折叠）。

- 数值标签写「危机压力 73/100」而非裸写「D73」；可在帮助层出现缩写。
- 到 P100 时说明还需核对主线、材料、等级和战斗状态，避免误判为自动胜利。
- 已成功/失败世界保持可查看，但不能再执行非法指令。
- **验收**：任意世界卡可回答「现在危险吗」「在做什么」「差什么才能结束」。

### 6.4 重大事件与援助（S05/S06）

- 每个事件含：**发生什么、选择、实际费用、可能收益/风险、默认处理、剩余期限、操作反馈**。
- 援助使用现有 preview 合同，同屏展示来源扣除、目标实际增益、冷却和导致来源终局资源不足的警告。
- 不可用状态列出具体原因，不仅让按钮变灰；重复点击不重复扣费。
- **验收**：玩家在确认前能复述这次操作的主要好处与放弃的机会。

### 6.5 队伍与战斗（S07/S08）

- 队伍展示「我有什么构筑 / 为什么会在战斗生效」，重要组合用中文描述而非只列攻击与辅助槽名。
- 选技可自动处理，但玩家主动三选一需看到槽位限制、已拥有技能及预期方向。
- 战报先展示结果（化解威胁/获得资源/承受损失），其次才是三波细节；战斗收益**不能凭 UI 额外结算**。
- **验收**：玩家能从一场战斗看出「战技有什么用」「和本世界救援有什么关系」。

### 6.6 手记、结算、档案（S09/S10/S13）

- 手记按「重大事件 / 玩家决定 / 自动日常 / 战斗 / 发现」分类或分级，默认展示主要条目；保留可查询细节。
- 结算分为：本局救援总结果、逐世界结束原因、关键选择回顾、下局建议；系统不确定时用「主要影响因素」而不是伪造确定因果。
- 局外先提供已实现的永久收藏、称号与历史进度；未实现属性加点或升级时不要出现「可以购买强化」暗示。
- **验收**：失败玩家能说出至少一个可改变的策略，而非只知道自己「输了」。

### 6.7 帮助 / 常见问题（S11）

至少含六个极短模块：

1. **怎么玩**：分身自动行动，玩家调整策略并处理重大事件。
2. **怎么赢**：救援准备、终局资格、时间和危机相互制约；P100 不是通关。
3. **看数值**：准备、危机、资源、等级、AP、灵魂和冷却的可读中文。
4. **如何选择**：成长/救援/排险/战斗差别及适用时机。
5. **跨世界救援**：来源会付出费用，不是免费资源复制。
6. **继续/存档**：暂停、倍速、自动保存、本地保存和只读页面。

入口：首页以及游戏进行中的顶部「? / 帮助」；短教程可跳过、从这里重看。常见问题要覆盖「为什么按钮灰了」「为什么 P100 仍没胜利」「为什么看不到第二个世界」「为什么刷新后暂停」。

### 6.8 **正式设置页（S12）——本轮特别补足**

设置不应等于「把所有按钮藏进去」；**频繁调整的模拟倍速与策略仍留在相应游玩页面**。设置专门处理低频的全局偏好和数据说明。

| 分组 | 控件 / 内容 | 默认与规则 | 优先级 / 状态 |
| --- | --- | --- | --- |
| 显示 | **文字大小：标准 / 较大** | 中文按钮、弹窗、HUD 随之调整，不能横向溢出；保存偏好。优先尊重系统字号 | P0 [缺口] |
| 显示 | **动画：跟随系统 / 减少动画** | 默认跟随 prefers-reduced-motion；如给额外开关，不应使隐藏内容无法访问 | P1 [缺口] |
| 新手体验 | **重新查看玩法帮助** | 不重开游戏、不重置进度；从帮助入口进入 | P0 [缺口] |
| 新手体验 | **引导显示偏好** | 已跳过提示不重复强弹；可从帮助页重看 | P1 [待与 B/A 整合] |
| 游戏数据 | **当前存档状态** | 「保存在本浏览器」「上次保存结果」「当前是否只读」；不承诺云同步 | P0 [警示已有，专页缺口] |
| 游戏数据 | **重新开始本局** | 与当前新局动作同源，明确是否覆盖 RunState、是否保留 ProfileState，二次确认 | P0 [确认逻辑需验收] |
| 游戏数据 | **清除所有本地进度** | **仅设计候选，不得在未确保恢复/二次确认前贸然上线**；明确本局与永久收藏均会受影响 | P1 [可选，涉及不可逆数据] |
| 声音 | 背景音乐 / 音效 / 音量 | **只有实际接入音频才显示真实可用控件**，不要做空开关；默认不强迫播放 | P2 [未确认音频系统] |
| 游戏模式 | 战潮开关 | 已存在于新局准备区域；影响本局生成，**不要在设置页伪造中途切换** | 已有入口，需说明 |
| 信息 | 版本号、更新记录、隐私/数据说明、反馈方式 | 与现有真实版本及审核材料一致；不要填未配置邮箱 | P0/P1 [待核对入口] |
| 语言 | 简体/繁体/英文 | **没有真实完整本地化前不显示切换控件** | P2 [可选] |
| 云同步/账号 | 登录、同步、恢复码 | **现版本没有后端，不做假设置，不承诺跨设备** | 暂不做 |

设置页的危险操作必须与普通偏好分区，并明确「返回」和「取消」。任何偏好保存失败要有可恢复提示；设置不应擅自改变游戏胜负、RNG 和已发生的历史。

以下通常被忽略，但决定 H5 游戏是否像正式产品。

| 功能族 | 必须处理的行为 | 设计约束 | 优先级 |

| 音频与触感 | 音乐、音效、振动 | 不在没有内容/权限/平台适配前假装存在 | P2 |

## 8. 核心规则与内容设计规范

### 8.1 保持的机制

- 每个世界每天**仅一个主要自主行动**。
- 同一种子、状态和操作顺序结果可复现；引导及 UI 不能消耗随机数。
- 重大事件超时有自动结果，不能因教程或弹窗永久卡住。
- 战潮三波是**同一次战斗结算**，不可重复掉落。
- P100 不是直接获救，必须通过终局等级、材料、标记与战力资格。
- 援助/融合费用、冷却、合法性由引擎与共享合同确定，预览不新造经济规则。
- 不改变 Profile/RunState 持久化结构，除非通过兼容性设计审查。

### 8.2 内容不再只追求事件数量

后续每一条事件或剧情分支必须具备**内容契约**：

| 字段 | 要求 |
| --- | --- |
| 稳定 ID / 世界 | 独一无二，玩家文本不当作逻辑键 |
| 情境与动机 | 玩家为什么关心这个人/地方/危机 |
| 触发与失效条件 | 所需阶段、时限、排他与重复规则 |
| 玩家可选行为 | 文案、合法性、实际费用、风险与结果 |
| 自动处理 | 不操作时发生什么，不能卡主线 |
| 反馈与日志 | 事件结果如何说明、进入哪类手记 |
| 经营/战斗连接 | 这件事影响资源、威胁、战技或终局哪一环 |
| 审核与可达性 | 文本导出、术语解释、手机空间预算 |
| 测试 | 正常、拒绝、边界、幂等/旧档容错 |

三世界应在**目标障碍、持续压力、资源意义、事件抉择与战斗策略**上真正不同；不要仅换名称、换数值曲线。新增内容先写设计意图与测试，再写文案和规则。

### 8.3 产品明确不做的事

- 现阶段**不做**强制每日手动点「成长、采集、战斗」的五键控制台。
- **不做**新的通用增量倍率/离线挂机，除非后续独立设计实验取得玩家体验与平衡证据。
- **不做**没有实际后端的云存档、账号、联机、公会。
- **不做**纯装饰、无实际行为的设置按钮。
- **不做**未获授权就删除现有真实本地存档。
- **不做**把科技 HUD 改个颜色就称为像素生存 UI。

## 11. 每个功能必须具备的规格模板与验收方法

以后提新增功能/页面，至少回答：

1. **玩家问题**：用户为何需要它？对应哪个具体行为/抱怨？
2. **入口与触发**：从哪里来、何时出现？当前是哪一层页面？
3. **界面内容**：首屏必须看到什么，哪些折叠？
4. **玩家动作**：能点击什么，选项的费用与后果是什么？
5. **五种状态**：未开启、正常、不可用、失败、完成。
6. **真实数据源**：RunState/规则合同/设置偏好/纯文案？不能另外发明判定。
7. **存档影响**：是否持久保存、刷新/多标签页会怎样？
8. **交互与无障碍**：手机、字号、触控、安全区、返回/取消。
9. **验证证据**：Vitest/Playwright/实际截图/真实试玩四种证据分别有无。
10. **发布影响**：文本、隐私、SDK/权限、权属与审核。

### 11.1 建议的真人首玩验收（尚未执行）

招募或邀请 **5 名未读过项目文档的人**，在手机上执行以下任务（样本目标是**项目内启发式测试**，并非行业通用达标线）：

- 前 60 秒说出本局目标和「自动模拟」与「玩家决定」的区别。
- 三分钟内找到目前最危险的世界及继续/暂停按钮。
- 在首次事件出现时，说出选择的代价和不处理的结果。
- 首次战斗后说出战技给世界带来的实际帮助。
- 局末描述一次成功/失败原因，知道下一局能做什么。
- 找到帮助与设置、理解存档在本地而非跨设备同步。

**候选门槛**：至少 4/5 人在不看外部说明、不接受观察者提示的情况下完成每项核心任务；若未达到先改 UI 和文案再加教学弹窗。真实数据应记录时间、卡点与误操作，不得编造测试结果。

### 11.2 自动化验收与发布门禁

- 逻辑：Vitest 不变量、规则合同、种子可复现。
- 浏览器：Playwright 首次开局、导航、跳过引导、事件、援助、战技、结算、刷新恢复、只读标签页。
- UI：320/375/390/430 CSS px、较大字号、reduced-motion、触控与安全区、无遮挡。
- 稳定性：IndexedDB 写失败暂停/重试、损坏读档拒绝覆盖、Web Locks 接管不丢进度。
- 文本：text:check、动态模板导出、人工审核台账。
- 部署：主线 CI 和 Pages build/deploy 只能证明自动化发布成功；真机与平台上架另验。
