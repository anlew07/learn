# 2W · 同屏自动遭遇验证（Loop Hero 参考）

> 基线：`main@d41e2a5`。候选方向获用户认可：幸存者式表现不作为第二套独立模式；模拟、探索、战斗属于同一个世界。此 PR 只实施正式主场景的可回看战斗切片，不宣称实现实时可干预的权威战斗。

## 玩家问题与可观察目标

玩家不希望从模拟器跳去一款独立动作游戏；希望看到分身自动活动、遇敌清剿、继续模拟，而不是只有文字。参考《Loop Hero》自动行进与玩家调整风险/发展策略的关系，但不照搬固定环形路线或卡牌摆放。

第一步利用已有 **正式 Engine 的每世界每日自主行动、唯一波次结算与 `lastCombat.spectacle`**，在固定世界场景中显示最近完成的一次战斗：
- `lastDecision.actionId === "fight"` 且 `lastCombat.day === run.day - 1` 时，用已有真实波次数量/击退数渲染小型敌群、技能光效与角色轻量走位。
- 主屏标注“上日交战 / 击退 X/Y”，明确是上一日的**战斗回顾**，而不是本秒的权威实时命中；世界继续按全局日历推进。
- 玩家原有“策略”“关键事件”“跨界援助”仍是正式命令。改变长期策略只影响后续自主行动，不篡改已完成战果；战斗画面不额外发奖。
- 正式标题页收为单一“开始/继续冒险”入口；移走首页的独立「雾谷出击 75 秒动作试玩」次入口。实验仍可直接访问 `?mode=sortie`，正式存档与实验存档继续隔离，不删除任何进度。
- 非战斗行动不生成假怪物；没有启用战潮或损坏/旧档缺少 `spectacle` 时不渲染遭遇。暂停、后台、减少动态效果时静止，切换世界停止旧场景 Canvas。

## 边界

此版**不是**新的实时 AI 寻路/战术战斗，也不执行真实的瞬时操作干预；不能把“演出攻击击退”冒充一份新战斗记录。保留现有独立出击实验入口和存档，不改正式存档版本/奖励/危险度/经济/世界主循环，不创建第二场按秒结算的战斗。

下一个可否通过的核心假设：玩家从战斗回顾中能看懂“哪一天清剿了什么、损失/收益已发生、调整策略会影响下一次”，才考虑把**权威战斗时间线**从一次性日结算进一步改成可暂停、可干预的实时遭遇。那将改变规则与存档，需先做单世界/固定种子实验和明确迁移设计。

## 验收

1. 同一真实 `Engine.step` 结果，对 `getStageView` 重复观战 10 次，世界与资源、存档 JSON 完全不变。
2. 上日实际打过且有波次数据才出现战斗回顾；切日、切世界、停波次、旧档、战败世界不显示虚假战况。
3. 手机 320×568、390×844、430×932 场景/策略按钮可见，画面非阻塞；Playwright 使用真实 Engine.step 测试档验证刷新后正式主屏自动呈现遭遇，观看不多结算；标题页只出现正式游戏入口，但独立试验深链仍可用。
4. CI lint / Vitest / Vite build / balance / Playwright；未完成的真实手机用户理解测验明确记录。
