# 2AE · 跨界枢纽与世界界门

## 玩家问题

当前多世界已经真实并行，但主屏顶部主要依靠小型文字标签切换。玩家能看到数量变化，却不容易把「一个救援名额如何接入新世界」理解成持续穿越的过程。

## 方案

在固定游戏 HUD 的「并行世界」计数入口打开跨界航路抽屉：

- 三个界门固定对应引擎中的三个并行名额（slotId），不是三种额外游戏模式。
- 已开启界门展示真实运行中的世界名称、世界序号、救援准备、危机压力与分身等级。
- 尚未开放的名额显示下一次成功救援所需条件；失败后空置的名额明确显示通道中断，不虚构替代世界。
- 点击已开放界门只复用现有世界切换行为；当前新手聚焦阶段继续遵守既有不可切换限制。
- 穿越记录只读取本局已经结算的世界历史。

## 规则边界

这是只读导航与世界关系可视化，不新增传送费用、传送动作、资源、解锁算法、随机事件或模拟状态。打开、关闭、浏览和切换观察均不得推进天数、改变暂停状态、支付资源、抽取 RNG 或写入存档。

名额使用 RunState 的 slotId；展示的「第 N 界」使用 worldNumber。两者不可混为一谈：同一名额在成功救援后会接入新的 worldNumber。

## 视觉与移动端

沿用项目现有石木材质、原创世界色彩和硬边像素风。三道界门通过形状、符号与材质色区分；320px 下保持三列可读，抽屉内部滚动，不产生整页溢出。

## 验收

- Vitest：新档 1 门开放、首救援后 2 门开放、满额 3 门、失败空槽、HTML 转义和新手聚焦限制。
- Playwright：320×568 / 390×844，实际 Engine.step 触发首救援，验证门数变化；三门开放时切换观察世界，并确认 RunState 未变化。
- 不改变引擎、存档协议、经济、RNG 或现有世界解锁条件。
- GitHub Actions 和真人手机视觉验收分别记录；CI 不替代 Android/iOS/TapTap WebView 真机确认。
