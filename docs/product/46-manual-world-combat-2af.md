# 2AF · 本源意识接管分身战斗设计合同

> 状态：**设计草案 / 等待玩法验证，不代表已实现或批准数值**。
> 基线：2026-11-24 `main@d4c044e283c32a0d523da0cd331817168a69d855`。
> 关联：正式世界同屏遭遇 2W、正式战术支援 2X、行动演出 2AA、世界名额扩张 2AC、救援成长反馈 2AD；2AE 跨界航路入口已由 PR #128 合并进入 main。
>
> 本合同只收敛“玩家如何在同一模拟器内接管一个分身的战斗”。不修改当前正式规则、存档、战斗结算或 UI。

## 1. 核心定位

玩家是多个世界的本源意识。分身平时自主生活、发展和应对危险；当真实战斗发生时，玩家可以选择让分身自主处理，或将意识降临到其中一个分身，亲自控制战斗。

**这不是独立动作游戏模式，而是正式世界模拟中的一种战斗参与方式。**

核心操作已经由用户确认：

- 普通攻击自动进行；
- 玩家手动控制分身走位；
- 战技由玩家主动选择；是否还要由玩家按键主动释放，作为下一步单变量体验验证。

玩家负责位置、时机和战术判断，分身负责自动索敌与普通攻击。

## 2. 一句话循环

**世界自主演化 → 真实遭遇出现 → 玩家选择自动处理或意识接管 → 战斗结果进入该世界当日结算 → 分身恢复自主行动 → 玩家继续观察和经营其他世界。**

不应出现“从模拟器退出、进入另一个游戏、战斗后回到另一份营地存档”的割裂感。

## 3. 遭遇触发与接管边界

### 3.1 只在真实战斗发生时进入战场

以下情况允许生成战斗遭遇：

- 当前世界的自主行动确实选择了排险/清剿；
- 已有威胁或重大事件合同明确要求战斗；
- 后续经独立设计批准的主动讨伐行动。

采集、修炼、普通探索、资源援助等非战斗行动不得为了展示战斗而生成假敌人。

### 3.2 每场战斗都允许自动处理

真实遭遇出现后，按玩家当前的战斗参与偏好处理：

- **自主处理**：分身由 AI 控制，快速得到同一遭遇模拟器的结果；
- **意识接管**：玩家控制走位，并决定战技构筑；战技释放方式另行验证；
- **战斗中托管**：玩家可把控制权交还 AI，AI 从当前战斗状态继续完成，不重置战斗。

首个关键遭遇应明确提示这两种方式。普通低风险战斗不应频繁弹窗打断；高危、精英和首领遭遇才优先询问。默认偏好可记入设置，但不能替玩家自动做付费、援助或不可逆决定。

### 3.3 一次只接管一个分身

同一时刻只能有一个分身接受玩家直接控制。战斗中可以查看其他世界的简要状态，但不能同时操纵另一个分身。若要切换世界，先托管或结束当前战斗。

## 4. 战斗操作合同

### 4.1 普通攻击：自动

- 自动寻找攻击范围内的合法目标；
- 默认优先最近且仍存活的威胁，距离相同时使用稳定 ID 决胜；
- 按武器攻击间隔自动发射/攻击；
- 玩家移动时普通攻击不中断；
- 没有合法目标时不空放攻击；
- 伤害、射程、攻速由世界成长、装备/构筑和已验证的营地投资共同决定。

不增加普通攻击按钮，也不要求玩家持续点击。

### 4.2 走位：手动

- 竖屏左下角虚拟摇杆；
- 八方向输入，松手立即归零；
- 走位可以躲避近战接触、投射物和范围攻击；
- 场景边界、障碍和碰撞由战斗规则决定，不依赖 Canvas 绘制帧；
- 摇杆不能遮挡角色、主要敌人和必要战场目标。

第一版沿用现有移动输入和固定步进思路，不引入复杂寻路或物理引擎。

### 4.3 战技：玩家选择，释放方式待验证

将“选择构筑”和“战斗中如何释放”分开，不把尚未确认的操作强加给玩家：

1. **选择**：遭遇开始或成长节点出现候选时，玩家从少量战技中选择/替换；需要选择时暂停战斗，避免触屏误操作。这是本轮已确认的玩家责任。
2. **释放候选 A——手动施放**：选定战技后显示技能按钮，玩家决定时机点击释放；冷却、充能和效果清晰可见。
3. **释放候选 B——自动施放**：玩家决定携带/升级哪种战技，战技按冷却或触发条件自动执行，玩家不必额外分心按键。
4. **目标辅助**：无论采用哪种释放方式，首版都不要求手动瞄准；技能按规则自动选择最近威胁、周围目标或自身防护范围。
5. **托管**：交还 AI 后，AI 使用同一战技配置和规则继续战斗；不能重置冷却或额外获得一次释放。

首个切片只开放 **1 个可选择的战技**。先比较 A/B 两种释放方式对操作负担、时机决策和战斗结果的影响，再决定是否保留主动按钮。第二个主动槽、复杂连招和多技能轮盘暂缓。

现有“驭雷符 / 聚灵阵纹”可作为原型候选，但需要重新验证；当前出击原型中的自动触发行为不能直接视为已经满足玩家选择权。

### 4.4 最小战斗 HUD

- 顶部：世界名、分身生命、当前遭遇目标/阶段；
- 战场：分身、敌人、投射物、可交互目标；
- 左下：虚拟摇杆；
- 右下：已选择战技的图标/状态；若验证通过手动施放，再显示按钮及冷却；
- 角落低权重入口：托管 / 撤离；
- 不在战斗画面堆叠长日志、资源报表和多世界详情。

战斗结束后使用简洁结果层说明击退、受伤、威胁变化、资源变化及下一步，再返回原世界场景。

## 5. 世界时间与多世界结算

这是防止系统割裂和存档漏洞的关键规则：

- 战斗持续的现实秒数**不等于**游戏内经过的天数；
- 一次遭遇只替代当前世界当天的一次主要行动，不额外赠送第二次行动；
- 玩家接管期间不因 45/75 秒战斗而让其他世界连续跳过数日；
- 当前日结算完成时，其他仍运行的世界各自执行当天唯一一次自主行动、危机压力和事件结算；
- 被接管世界以真实战斗回执替代当天原本的自动排险行动；
- 完成后全局日期只推进一次。

玩家可以在战斗 HUD 看到其他世界“本日行动待结算/已结算”的简要状态。是否在战斗过程中提前结算其他世界，属于后续性能与事务设计，不应改变“每世界每天只有一次主要行动”的规则。

## 6. 战斗结果必须真实进入模拟器

战斗不是独立奖励副本。唯一结果必须回写当前正式 RunState：

| 战斗事实 | 对正式世界的影响 |
|---|---|
| 实际击退与威胁进度 | 推进/解除当前威胁，按现有合同结算 |
| 实际受伤 | 记录分身伤势或短期状态 |
| 战斗失败/撤离 | 付出当天主要行动机会，按规则承担危机或威胁后果 |
| 技能和构筑表现 | 影响本场结果，并留下可解释战报 |
| 资源掉落/拾取 | 只能进入当前行动的既有收益上限，不得额外重复发奖 |

不采用“击杀一个敌人就额外发一份灵石”的无限刷取方式。击杀数、拾取数、资源奖励和危机缓解必须由同一份战斗回执统一核算。

首版不采用永久死亡。生命归零时优先表现为重伤撤离/本场失败，真实后果进入伤势、危机和行动结算；是否存在世界终局仍由正式世界规则决定。

## 7. 战斗时长与节奏（待实验）

当前独立出击原型的 75 秒是实验参数，不应直接成为所有正式遭遇的固定时长。

建议首轮验证：

- 普通遭遇：约 30–45 秒；
- 精英遭遇：约 45–75 秒；
- 首领战：单独验证，暂不纳入首个垂直切片。

普通遭遇应足够展示一次走位和战技决策，又不能让玩家每天被迫打长战斗。低风险日常排险应能快速自动处理。最终时长以移动端实测和固定种子平衡结果决定。

## 8. 统一模拟器：目标架构与现有基础

当前 main 已有：

- `Engine.step`：按游戏日推进所有运行世界；
- `selectAutonomousAction`：为分身选择自主行动并解释原因；
- `simulateSurvivorWaves` / `wave-combat.js`：权威日结算战斗与构筑收益；
- `Engine.settleSortie`：验证战斗轨迹、克隆 RunState、以一次日结算替代灵灾世界主要行动，并使用结算账本防止重复奖励；
- `src/systems/sortie-sim.js`：60Hz 固定步进、移动、自动索敌攻击、敌人追击、投射物碰撞及战技原型；
- `src/services/persistence.js` 与独占会话：正式存档和多标签写保护。

当前独立 `sortie-sim` 使用单独试验存档、固定 75 秒任务和自动触发技能，不能直接挂到正式主屏当作已完成的接管系统。

### 目标原则

1. **一个权威遭遇模拟器、两种控制器**：玩家输入或 AI 输入都驱动同一战斗规则；自动处理不是另一套奖励公式。
2. **固定步进与渲染分离**：战斗规则不能由 requestAnimationFrame 的实际帧率决定。
3. **单次事务结算**：战斗结果校验后一次性进入正式 RunState；回看、刷新、托管、重复提交不得再次支付或奖励。
4. **可恢复**：遭遇开始时保存 pending 标识；战斗期间保存可恢复快照/输入记录；刷新后可继续或安全交给 AI，不丢失正式档。
5. **旧规则渐进迁移**：当前三波日结算仍是正式基线。只有固定种子证明新遭遇模型不破坏胜率、危险梯度、资源和终局资格后，才逐步替换对应战斗路径。

### 现有实现的复用判断

- 复用 `sortie-sim.js` 的固定步进、移动、自动攻击和投射物处理思路；
- 复用 `Engine.settleSortie` 的轨迹校验、克隆结算和幂等账本模式；
- 复用 `wave-combat.js` 的战斗收益上限和现有构筑语义；
- 复用现有 Canvas 2D 世界场景和世界精灵；
- 不新增 Phaser/PixiJS 等大型引擎，不另建正式游戏入口，不另建正式存档命名空间。

是否抽取通用 `encounter-sim`、如何迁移三波战斗，须在单世界原型完成后再定，不在本设计文档中预先锁定代码结构。

## 9. 首个可玩垂直切片

只做灵灾世界一个真实排险遭遇：

- 从正式世界状态触发，不提供独立试玩标题页；
- 一个分身、一种普通敌人和一种远程敌人；
- 自动普通攻击 + 手动走位；
- 一个战技选择节点（从两个候选中选择），并对比手动施放与自动触发；
- 自动托管与玩家接管可在同一场遭遇中切换；
- 战斗结束后只结算一次当天主要行动；
- 回到原世界，展示真实世界状态变化；
- 先不做第二世界实时战斗、多人协同、复杂首领、多主动技能槽和大规模掉落系统。

## 10. 验收门禁

### 规则与数值

- 至少 40 个固定种子，比较自动控制与玩家输入脚本；
- 比较击退、受伤、剩余生命、威胁进度、胜败、资源、危机和实际继续出击率；
- 同一输入轨迹可确定性重放；
- 玩家接管不能绕过等级、资源、主线或首领资格。

### 存档与事务

- 战斗中刷新/关闭后可恢复或安全托管；
- 同一遭遇重复提交不重复推进日期、不重复扣费、不重复发奖；
- 正式 Run/Profile 与旧独立试验档隔离；
- 多标签只允许一个写入者。

### 手机体验

覆盖 320×568、390×844、430×932：

- 摇杆拖动、反向、松手归零、多指操作；
- 走位时自动攻击不停止；
- 技能选择暂停明确，技能释放和冷却反馈明确；
- 托管/撤离不会误触；
- 页面不滚动、不溢出，后台恢复不产生补帧伤害；
- 真实玩家能在不读说明的情况下理解“我控制走位，角色自动攻击”。

## 11. 当前已确认与待验证

**已确认（用户明确选择）**

- 自动普通攻击；
- 手动控制走位；
- 战技由玩家主动选择；是否手动施放仍待实验；
- 战斗属于模拟器内部的世界遭遇，不作为独立游戏模式。

**本合同提出、仍待实验验证**

- 首版只放一个战技选择位；主动按钮是否必要待实验；
- 普通/精英遭遇时长范围；
- 自动处理与玩家接管共用一个权威遭遇模拟器；
- 战斗期间全局日历不按现实秒数推进；
- 低风险战斗默认自动，高危遭遇优先询问；
- 生命归零采用重伤撤离而非永久死亡。

**明确暂不做**

- 复制完整《吸血鬼幸存者》海量弹幕和大量技能升级；
- 玩家手动瞄准普通攻击；
- 每场战斗都强制玩家操作；
- 战斗独立副本、独立正式存档和独立奖励经济；
- 在未验证前把当前 75 秒出击原型直接并入正式世界；
- 同时控制多个世界分身。

## 12. 后续实施顺序

1. 先做单世界战斗规则原型，验证自动攻击、手动走位、战技选择，并对比手动施放/自动触发；
2. 建立 AI 控制器，让自动处理与玩家接管使用同一遭遇规则；
3. 接入正式世界当天主要行动和唯一结算事务；
4. 接入可恢复存档、托管切换和多世界日结算；
5. 完成移动端 QA、固定种子平衡和首次玩家理解测试；
6. 通过验收后再扩展尸潮、兽潮的世界专属敌人与战技。

> **最终目标：玩家平时经营多个正在演化的世界；当某个分身真正遇险时，玩家可以降临帮助它战斗。战斗改变世界，世界成长又反过来改变下一场战斗。**
