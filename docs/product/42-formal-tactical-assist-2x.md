# 2X · 正式世界的真实战术支援（连续战斗方向·第二步）

> 基线：`main@a0e6c67`，2W 已合并及 Pages 成功。本 PR 是**权威战斗干预的最小切片**，不是声称实时按秒交锋已经完成。

## 玩家问题与范围

2W 让已经结算的战斗显示在原地图上，但玩家仍无法通过战斗附近的操作改变真实胜负数据。当前正式模拟由 `Engine.step` 按天结算，一旦跳过结果再播放回放，任何之后的按钮都不应修改过去战斗。

本步先验证**同一世界、提前布置战术 → 分身自主排险 → 权威三波清剿发生变化 → 同屏展示真实增益**：
1. 正式世界 HUD 原「战报」位置变成「战术」，战报移至已有「更多功能」抽屉，避免增加 HUD 行。手机按实际触摸操作。
2. 玩家消耗 **1 AP** 对当前仍在运行且启用三波防线的世界布置一次「集中火力」。正式引擎记录该命令，保存后可安全刷新、重放操作 ID 不重复扣费。
3. 分身仍按原有长期策略每天进行**唯一一次自主行动**。仅当该世界下次真正选择「排险」时，从权威 `simulateSurvivorWaves` 对三波增加有限攻击力（`wavePower=4`），一次使用后消失；其余日子不会扣第二次费用。
4. 战后由**同一次权威结算**计算“比原三波额外击退几只”，并按真实额外击退给予当天自然危机压力的缓解（每新增击退潜在 0.25，最多 2.5）。若原已全清或本日自然压力不足，只显示实际生效的数值，不承诺虚假的额外收益。
5. 改造后的原主屏「昨日战报」显示增加的真实击退和危机缓解。原引擎等级、奖励、事件、RNG、正式 Run/Profile 的批量持久化与独占锁不改；旧档不带战术字段也正常工作。

**玩家代价与风险**：支援有 AP 机会成本；如果世界在下次排险前已结束，AP 不退。不能叠加未使用的相同支援；首次结算后才可再买一份（仍需满足 AP）。不启用三波防线时不可购买。

## 为什么不直接把正式 Engine 改成逐帧实时？

当前正式引擎是一日一次权威行动，另有仅作试验用的 60Hz `sortie-sim`、事件暂停、单写者锁和存档回放。把它们合并为逐帧正式战斗需设计一个事务内的“遭遇准备、战斗持续、一次结算、掉线恢复与自动托管”，否则会发生刷新多发资源或行动重复。本步先把最有价值的一条用户选择接到**已有权威战斗**，通过固定种子对照测是否改变真实结果，再决定是否承担正式实时化的迁移风险。

## 设计依据与方案选择

- 《Loop Hero》官方：角色自动面对敌人，玩家在遭遇前管理风险与发展（https://store.steampowered.com/app/1282730/Loop_Hero/）。只参考“自动行动 + 有代价的间接干预”，不复制其卡牌、路线或素材。
- MDN 的 `requestAnimationFrame` 与 Page Visibility API：后台节流导致真实逐帧推进需独立、可恢复的权威状态，而不是依赖 Canvas 帧数（https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API）。
- 已检查现有 `src/systems/survivor-waves.js`、`wave-combat.js`、`src/engine.js`、`sortie-trace.js`。本次复用已验证的 3 波固定种子结算、操作 ID 幂等及 SaveRepository；新增 **0** 第三方依赖、素材与许可证负担。

## 测试/收口门禁

- Vitest：AP 单次消费、跨刷新状态、重复 ID、波次关闭、世界不可用、空 AP、40 固定种子成对对照，观战 10 次不能更改权威状态。
- Playwright：320×568、390×844、430×932 真实触摸「战术 → 投入 1AP」，刷新后保持待命、无第二次购买，真实引擎副本战斗有效、正式 IndexedDB 不因副本观战改变。
- 全量 CI：lint、format、文本导出/审核、Vitest、构建、数值矩阵、联动出击回放、浏览器；验收后再考虑合并与 Pages。
- 暂未覆盖：战场中的实时走位、遭遇中技能改变当场胜负、掉线后继续未结算实时战斗、真机首次玩家理解测试。这些必须进入下一步独立设计与验证，不能把 2X 当作已完成。
