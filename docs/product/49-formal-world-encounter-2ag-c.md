# 2AG-C · 正式世界遭遇接入

> 依赖：2AG-A 同场控制器切换、2AG-B 默认自动战技释放。
> 范围：只接入灵灾世界的真实排险行动；废土与兽潮保持原有自动模拟。

## 目标与玩法边界

灵灾世界当天的权威下一行动必须确实为 `fight`，才允许创建实时遭遇。实时战斗不是新模式，也不是额外日程：

1. 世界日历停在当前日。
2. 灵灾分身进入同一套固定步进战斗模拟器。
3. 玩家可选择本源意识接管，或让 AI 自主处理。
4. 玩家接管期间可随时交还 AI；控制权切换不重建 battle、不重置冷却、敌人、弹道或生命。
5. 遭遇结束后，灵灾排险替代当天原本的 `fight` 行动；其他世界照常完成本日行动。
6. 正式世界日期只推进一次，奖励和行动账本只提交一次。

## 触发门禁

`Engine.previewNextAction(run, "lingzai")` 在一次性副本中预测当天真实行动。只有同时满足以下条件才允许接入：

- `actionId === "fight"`
- 世界仍处于 running
- 没有激活中的待处理事件
- 没有待选择的战技构筑
- 没有已存在的未完成遭遇

因此不会把训练、采集或普通观察伪装成战斗，也不会让实时战斗覆盖尚未处理的重大事件。

本阶段只对灵灾世界开放。废土与兽潮仍由既有世界引擎自动结算，不复制一套新战斗系统。

## 控制方式

首次遭遇暂停模拟并询问：

- **让分身自主处理**：由 2AG-A AI 控制器完成整场战斗。
- **本源意识接管**：玩家用移动摇杆控制走位，普通攻击自动进行。

本局会记住首次选择。玩家接管时可随时交还 AI，AI 从当前 battle 状态继续。战技沿用 2AG-B 结论：普通攻击自动，战技选择后默认自动释放，不增加强制技能按钮。

## 可恢复的 pending encounter

正式 RunState 保存最小可重建记录：

- 遭遇 ID、世界 ID、游戏日
- 确定性种子、当前危险值、剑台等级和任务 ID
- 控制器状态（choice / player / ai）
- 已执行的 tick、技能选择和撤离轨迹

不把 Canvas 或运行时 battle 对象直接序列化。恢复时从相同 seed 创建战场，再由 `replaySortieProgress` 逐条验证并重放已保存轨迹。这样刷新不会重置战斗，也不会信任客户端保存的任意坐标快照。

玩家战斗期间约每秒保存一次；暂停、切到后台、页面离开时也保存。重新打开页面会取得独占会话锁，先读取最新正式存档，再将未完成遭遇恢复为暂停状态，等待玩家继续。

如果轨迹或存档结构不合法，停止写入并保护正式档，不静默修复或丢弃未结算战斗。

## 权威结算与幂等

`Engine.settleEncounter` 不接受客户端传入奖励数字，只读取 RunState 中保存的轨迹，并再次执行权威重放：

- 遭遇 ID 必须对应当前 run/day。
- 当前危险值、剑台和任务准备必须与开始遭遇时一致。
- 当前真实下一行动仍须为 fight。
- 战斗必须已经结束。
- 结算沿用既有 `sortieLedger` 指纹和回执；重复提交相同 ID 只返回原回执，不重复发放资源或推进日期。
- 正式世界记录的行动 ID 为 `fight`，不是独立试玩用的 `sortie`。

旧的 `Engine.settleSortie` 仍保留原有独立出击语义和测试兼容；只有新的 `settleEncounter` 路径会将正式世界行动记为 fight。

## 验证

新增 Vitest 覆盖：

- 非 fight 行动不得创建遭遇。
- 激活事件和待选构筑阻止接管。
- 不完整轨迹恢复与技能选择暂停恢复。
- 玩家交还 AI 时同一 battle 连续运行。
- 结算只推进一天、其他世界照常行动、正式行动 ID 为 fight。
- 重复结算幂等、伪造轨迹不改变正式 RunState。
- pending encounter 的正式存档结构校验。

新增 Playwright 移动端闭环，覆盖 320×568、390×844、430×932：

- 从正式世界 debug 日推进入口触发真实 fight。
- 接管并操作移动摇杆。
- 中途暂停、保存、刷新。
- 从轨迹恢复后交还 AI。
- 验证正式世界只推进到下一日，战斗回执、fight 指标和其他世界行动均只结算一次。

## 暂不包含

- 不把实时战斗扩展到废土或兽潮。
- 不改战斗时长、敌人强度、掉落、正式经济、世界成长曲线。
- 不增加第二套存档仓库或独立试玩入口。
- 不改变现有 RunState 版本号；新增字段均可选，旧存档由 `Engine.restore` 补默认值。

下一阶段先做完整真人移动端体验和平衡验收，再决定是否扩展第二个世界；不能仅凭 AI 自动战斗胜率推断玩家难度。
