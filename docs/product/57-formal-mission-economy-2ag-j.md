# 2AG-J · 正式任务经济价值与控制成本配对实验

## 目标

2AG-H 已把「险地回收完成后主动撤离 +2 灵石」接入正式遭遇。下一步不改奖励数值，而是验证这项任务相对「稳妥巡护」是否有清晰、不过度占优的收益，以及玩家接管和额外耗时的实际代价。

## 配对方案

- 40 个固定种子，复用 2AG-F 命名；D0 / D45 / D80。
- 有效等级取 Lv1 与 Lv4 两个边界，覆盖 8 HP 与 11 HP。
- 每个相同 seed / danger / level 对比六组：
  1. 稳妥巡护 · AI。
  2. 稳妥巡护 · 玩家拾取路线。
  3. 险地回收 · 完成即撤离。
  4. 险地回收 · 完成后继续 15 秒。
  5. 险地回收 · 完成后继续 30 秒。
  6. 险地回收 · 坚守到底。
- 总样本 1,440 场；普通攻击、敌人、技能、掉落、任务奖励和正式奖励公式全部沿用当前配置。
- 玩家路线复用仓库现有确定性拾取／近敌规避输入；AI 使用正式 Encounter Controller。
- 每场均用 replaySortieTrace 权威重放，并核对结局、任务、受击、生命、击退、碎片和奖励回执。

## 核心指标

- 实际灵石、目标奖励、碎片折算、胜率、撤离率和死亡率。
- 平均战斗秒数、每战斗分钟灵石收益（仅用于观察操作时间效率，不等于现实墙钟或 campaign-day 吞吐）。
- 平均剩余生命比例、受击、击退、碎片和经验／进度。
- 分别与安全 AI、同路线安全玩家进行配对差值，避免把控制方式差异误判为任务奖励差异。

## 验收与裁决

本轮是研究脚本和 CI 门禁，不改 Engine、HUD、存档、经济或正式奖励。
不预设险地回收必须更好：如果它在所有危险档、等级和控制基线下都严格占优，应考虑降低奖励或提高任务风险；如果安全任务更稳定且资源效率合理，则保留两个任务的不同定位。
脚本控制不代表真人手机表现，不能用模拟胜率代替真实触控体验。

## CI

运行 npm run encounter:mission-economy:check，固定 1,440 场样本、验证任务奖励边界并逐场权威回放。
