# 灵灾出击 2K-C：营地储蓄与一次性准备的隔离实验

> 2026-11-18。基线：#74 2J 集成 7e6cd2ee91574ab837f6931f3fc38a5e298ed70e；参考 #74 2K 总控合同、2K-A Draft PR #90；工作 Draft PR #92。候选规则**未获产品批准**，不代表正式游戏存在新消费入口。

## 一、目的和既有瓶颈

第一次真实出击结算后比较三条策略：「不花费资源」「储蓄并在首次有 6 石时真实修复永久护灵剑台」「花 3 石购买仅下一场 +2 初始生命的准备」。第三种是**试验假设**，不是正式名称、成本或数值。

现有原型：75 秒固定出击、25 秒暂停选技；每击退 3 个敌人生成 1 碎片，每 3 碎片兑换 1 灵石，碎片兑换上限 2；胜利基本奖励 3 灵石。护灵剑台实价 6 灵石，永久灵刃伤害 1→2。2I-C/2J-C 的已集成结论为 518 个真实建成样本到第六场 0 回本（净差约 −6.6 灵石）；这是历史基线，不冒充本轮数据。

## 二、隔离引擎与真实经济流程

新增实验脚本仅在临时目录复制 src 和原有固定种子实验驱动，脚本退出即删除临时源码副本，不修改生产 src 文件。

1. 临时 createSortie 仅在存档的 prepared.charges 为 1 时以 8+2 初始生命开始真正的下一场。其他敌群、武器、技能、伤害、资源上限不变。
2. 临时 replaySortieTrace 和临时 Engine.settleSortie 读取**同一**购买状态，按固定 tick 重放战斗；成功结算时在原子克隆状态中消耗 charges 1→0。没有在正式回执上手动添加生命、胜率或灵石。
3. 购买函数从隔离档灵灾世界真实 resource 扣 3，生成 operationId、前后余额、消费次数记录。同 ID 重放不重复扣；不同 ID 不能重复买；首次结算前或待结算出击中禁止购买。
4. 储蓄策略在首次真实可支付 6 灵石时调用原生 previewSortieForge/buildSortieForge 建造，不直接预置 forgeLevel=1，也不采用假想减价。
5. 每场先 prepareSortieArchive，再跑真实 60Hz 敌群、弹道、拾取和技能选择，最终 settleSortieArchive → 临时 Engine.settleSortie；验证双世界回执、实际奖励、重复同 ID 结算幂等。
6. 危险 D0/40/75，战技 thunder/rune，路线 kite（绕场）、pickup（主动拾取）、reverse（每 12 秒中的固定 0.8 秒反向摇杆）。这不是凭空对拾取附加扣血。

**落地边界**：这只是可复现的临时影子引擎，不代表生产引擎能识别新的准备字段。任何正式消费必须另行通过产品批准、存档兼容、权威回放和 UI 验证，不能复制临时补丁直接上架。

## 三、指标、分母和拒绝门槛

- 固定 40 种子 × 3 危险 × 双战技 × 三路线，共 720 个**首场完全共享**的配对单元；分为不花、攒剑台、买准备三路线，观察第 2–6 场。
- 统计可投资与实际消费人数、消费当天、可继续出击人数、次场胜负翻转、真实受击与余命、击退、碎片、权威实得灵石、废土世界变化、含费用累计净灵石和真实回本人数。
- 只在**实际消费的样本**上计算投资效果；买不起者不当作成功购买，未能继续出击者不能虚报有战斗，终止后资源仅冻结用于账面比较。
- 不能因为余命增加 2 就认为有效；还应能改变高危胜败、后续获得资源或必要的容错，且不得对所有路线与技能形成单一最优选择。
- 第二场收益与六场成本分别报告。技能仍保留聚灵阵纹的独立防御价值。

## 四、工程安全测试

专项 Vitest 对照首次出击前禁止消费、真实一次扣 3、同 ID 幂等与异 ID 拒绝、刷新后结构恢复、出击过程中不可再次消费、pending 未完成战斗恢复无误奖励、权威双世界回执、重复结算、第二场耗尽与第三场不再附加 HP、非法状态不予结算、正式档隔离。原有正式 Run/Profile、主界面与 B 的奖励文件不动。

## 五、40 种子实验与 CI

最终 40 种子完整实测应以 #92 GitHub Actions 中 CAMP_CHOICE_2K_JSON 输出为证据；尚无对应成功日志时不能宣称候选有效或可长期回本。待 CI 最终记录后填充第二场、六场汇总与危险分层结论。

即使 Chromium Playwright、Vitest、构建和数值矩阵绿灯，也不等于 Android/iOS/TapTap WebView 或真人 3–5 分钟理解度通过。2K-B 如修改奖励系统，C 本轮利润和收益必须在共同集成分支重新复验。
