# 2AG-F · 世界构筑影响实时遭遇的进攻 / 防御实验

> 状态：**隔离实验，尚未接入正式世界规则或正式存档结算**。
> 基线：2AG-E-B，分支 `experiment/formal-combat-level-pressure-2ag-e-b-20261126`。
> 目标：验证现有世界战技构筑能否让同一套实时遭遇产生可感知的进攻 / 防御差异。

## 1. 为什么做这一轮

2AG-E 已证明有效等级增加生命储备有一定价值，但高危持续包围仍然无法解决。继续堆生命不是合适的下一步。

正式世界已经保存每个世界自己的战技构筑：

- `thunder`：攻击槽，清剿倾向；
- `sword`：攻击槽，拾取 / 资源倾向；
- `rune`：辅助槽，防御倾向；
- `thunder + rune`：已有进化记录「雷阵连锁」。

目前这些构筑主要进入日常波次结算，还没有真实影响实时接管战斗。本轮只实验其中两个可直接映射的效果，不改变正式 RunState。

## 2. 单变量候选

| 构筑 | 等级 0 | 等级 1 | 等级 2 |
|---|---|---|---|
| 驭雷符（进攻） | 每次雷击最多 1 个目标 | 最多 2 个目标 | 最多 3 个目标 |
| 聚灵阵纹（防御） | 护盾容量 1 | 护盾容量 2 | 护盾容量 3 |

规则边界：

- 只有选择对应战技时才生效，不自动同时获得两种效果。
- 驭雷符伤害、冷却、射程不变，只增加目标数。
- 聚灵阵纹初始仍只有 1 层护盾；每次原有 25 秒充能最多补充 1 层，储备上限随构筑等级增加。
- 每层护盾只抵挡一次真实伤害；不增加生命，不直接减伤。
- 不改变普通攻击、敌人属性、生成节奏、拾取半径、奖励上限、世界日期或资源经济。
- `sword` 与「雷阵连锁」暂不映射，避免同时引入拾取收益和组合技变量。

## 3. 实验矩阵

- 固定种子：每组 40 个。
- 危险档：D0 / D45 / D80。
- 操作脚本：固定站位、抵达险地回收点后坚守。
- 构筑档：驭雷符 Lv0–Lv2、聚灵阵纹 Lv0–Lv2。
- 总样本：1,440 场。
- 每场都通过同种子、同输入轨迹的权威回放核对。

比较指标：

- 胜率、剩余生命、受伤次数；
- 实际击退、碎片拾取；
- 雷击实际命中目标数；
- 护盾真实格挡次数；
- 险地守卫触发与回收完成率。

同一构筑内部只改变等级，技能选择固定为对应战技；不把不同操作脚本的绝对胜率直接当作玩家水平比较。

## 4. 本阶段交付边界

本分支只为实时模拟器增加可选的 `combatBuild` 实验输入、权威轨迹回放参数、固定种子脚本和单元测试；正式奖励回执结构保持不变。

**不会**把构筑快照写入正式 `pendingEncounter`，不会改变正式世界的战斗结果，也不会启用新的 UI 效果。

只有当配对数据证明效果真实、边界合理，下一阶段才把通过验证的构筑快照接入 `Engine.beginEncounter`、正式回放和移动端 HUD。若只是增加命中数字而没有改变击退 / 生存 / 资源结果，则不应直接合并为正式成长效果。

## 5. 验收原则

- 默认不传构筑时，旧战斗结果必须完全兼容。
- 等级只能是 0–2；非法字段或越界等级拒绝回放。
- 自动与手动释放共用相同的构筑上限。
- 护盾容量只增加储备上限，不凭空发放多层初始护盾。
- 每个固定种子结果必须能由权威轨迹完全重放。
- 脚本化压力实验不能替代真实手机玩家测试。

## 6. 2AG-F 实际结果（CI Run #898，完整 1,440 场）

40 seeds × D0/D45/D80 × 固定站位 / 险地回收点坚守 × 六种构筑档，所有战斗均执行同输入轨迹权威回放。

### 驭雷符目标数

| 操作脚本 | 危险档 | Lv1 雷击命中差 | Lv2 雷击命中差 | 击退差（Lv1 / Lv2） | 胜率 / 余命 / 受击 / 碎片 |
|---|---:|---:|---:|---:|---|
| 固定站位 | D0 | +0.33 | +0.33 | +0.05 / +0.05 | 全部不变 |
| 固定站位 | D45 | +0.10 | +0.10 | +0.05 / +0.05 | 全部不变 |
| 固定站位 | D80 | +0.47 | +0.50 | +0.05 / +0.05 | 全部不变 |
| 险地回收点坚守 | D0 | +0.27 | +0.27 | 0 / 0 | 全部不变 |
| 险地回收点坚守 | D45 | +0.17 | +0.17 | +0.02 / +0.02 | 全部不变 |
| 险地回收点坚守 | D80 | +0.05 | +0.05 | 0 / 0 | 全部不变 |

目标数增加确实增加了雷击命中，但没有形成可兑现的击退、胜率、余命或碎片收益。Lv2 在部分分组与 Lv1 完全相同，说明单纯扩大命中目标数并不能保证有效清场。

### 聚灵阵纹护盾容量

全部 6 个「操作脚本 × 危险档」组合中，Lv1 / Lv2 相对 Lv0 的：

- 胜率差：0；
- 剩余生命差：0；
- 受击差：0；
- 护盾格挡差：0；
- 碎片收益差：0。

原因不是护盾逻辑未执行，而是原有 25 秒充能间隔下，额外容量从未形成有效储备：每次真实受击消耗一层，充能到来时没有多余层数可存。**只提高容量上限属于没有触发条件的空升级。**

### 险地目标的额外观察

险地回收脚本在 D0/D45/D80 下均为 40/40 触发并完成回收点目标，但三档最终战斗仍全部失败（40/40）。目标完成与整场存活是两个不同结果；本实验的构筑候选没有改变这两者之间的关系。

### 裁决

**两种效果均不准入正式玩法，不接入 Engine.pendingEncounter、不写入正式世界存档、不展示为已生效成长。**

本轮是有效的负面实验：雷击命中不是击退价值，护盾容量不是实际格挡价值。后续不再重复扩大目标数或容量上限。

## 7. 与历史实验的交叉结论及下一步

- 2I-A / 2J-A 已否决单纯缩短雷击冷却、增加雷击伤害或提前触发时机；2J-A 的完整报告还显示危险暴露代理下降，并不必然带来真实受伤、击退或灵石收益。
- 2K-B 否决隐藏距离条件扣减保底奖励；2K-C 否决 3 石换次场 +2 HP 的消费规则，剑台也没有在第六场内回本。
- 2AG-E 的每级 +1 生命能改变少量低中危样本，但高危包围仍无法解决。
- 2AG-F 再次证明「多命中」和「多容量」仍不是玩家可感知的成长。

下一轮应先做设计级验证，而不是继续扫数值：进攻构筑需要真实打断 / 解除迫近威胁，防御构筑需要真实提供可用的初始防护或更及时的防护循环；同时检查它们能否改变回收目标完成后的撤离 / 继续战斗选择。每项仍需独立固定种子对照，不能把多种改动打包成一次成功。

**2AG-F 最终状态：工程门禁通过，产品效果门禁不通过；保留负面证据，不合并为正式成长。**
