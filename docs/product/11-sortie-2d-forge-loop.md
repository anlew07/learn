# 灵灾出击 2D · 护灵剑台、资源取舍与两场闭环

> 2026-11-17。此 PR 基于 [2C PR #67](https://github.com/anlew07/learn/pull/67)，依次依赖 [2B #66](https://github.com/anlew07/learn/pull/66) 与 [2A #65](https://github.com/anlew07/learn/pull/65)。尚未合并或上线正式游戏。产品规格见 [设计 PR #64](https://github.com/anlew07/learn/pull/64)。

## 这轮新增加什么

出击 75 秒（第一场）→ 真实战斗奖励落盘、双世界日 +1 → 回灵灾营地 → **唯一护灵剑台**支付 6 灵石、保存成功后点亮 → 第二场基础灵刃从 1 点升为 **2 点伤害** → 真实再结算另一天并展示两场击倒数与各世界变化。

第一次出击成功必有基础 3 灵石，从初始 4 变为至少 7，因此可支付 6。拾取的碎片依旧额外折算 0–2 灵石。失败/撤离没有基础收益，不提供“免费建造”。**灵石原本用于灵灾终局封印（旧资源需求为 10），修复剑台必然存在机会成本，不退款；不会消耗 AP 或额外推进一天。** 营地未修复时显示灰色基座，修复后显示亮起状态。不增第二设施、配方、建筑队列或工人。

## 数据与信任边界

- 只在 **独立试验档**的 `archive.run.sortieCamp` 保存 `{forgeLevel,buildReceipt}`；旧 2C 独立档缺失此字段时按 Lv0 读取，绝不改写正式 Run/Profile 版本或键，首次存入独立档时规范化。当前仍为同一原子单键 IndexedDB 写入，无新依赖。
- `previewSortieForge(archive)` 只计算价格/可用性/剩余灵石；`buildSortieForge(archive, operationId)` 返回新的克隆状态 + 回执，**不原地扣资源**。条件：当前未出击、已有真实已结算回执、灵灾仍运行、Lv0、灵石 ≥6；同 operationId 重试得到旧回执，不同 ID 在已建成时拒绝；无效 ID、异常等级或损坏回执拒写。
- 原来的单写 Web Locks、`persistCandidate` 写入失败冻结/显式重试流程直接复用。前端只在持久化成功回调更新建设 UI；保存失败仍使用旧资金与 Lv0，不让画面提前发奖。
- `createSortie(seed,danger,forgeLevel)` 记录**本场武器伤害**；每枚灵刃的实际命中用 `battle.weaponDamage`，不是单纯更换图片。**奖励复算的权威 `Engine.settleSortie()` 也从运行档 `run.sortieCamp.forgeLevel` 读取同一状态重新模拟完整轨迹**，因此无法仅向 UI 传一个假的“伤害 2”绕开真实记录。
- 跨世界原正常日结算、不重复主行动、不绕过终局检查；营地建设只改变灵灾资源与剑台状态，不改变废土 RNG，也不冒用既有 `world.build.pending` 战技觉醒槽。
- 结果页读已提交 receipt，显示本场真实伤害、拾取、P/D/XP/资源与废土行动。营地保留剑台修复前战斗击退数，第二场完成后与其作**真实比较**（击退总数不承诺必然增加；重点是同配置下妖狼实际命中次数降低）。

## 验收范围

- Vitest：首场之前不可建、首次胜利后资金门槛、一次性付款、重复 operationId、不足款与非法等级、单发灵刃对 2HP 妖狼的真实差异、两次世界日同步、IndexedDB 写入失败与重试、正式存档原键隔离。
- Playwright：320×568/390×844/430×932 营地无页面溢出；完整按键走位 → 25 秒战技选择 → 第一场实际生存胜利 → 领取 → 6 灵石建造 → 刷新 → 第二场正常走位生存 → 双世界日 +2 和真实前后战报；不借助直接灌奖励/修改战斗值。
- 生产构建、旧 Vitest 与 Playwright、固定策略/平衡矩阵均按当前 GitHub Actions 实际结果验收。**真实手机与 TapTap WebView 尚未验证时不能宣称通过**。

## 切片之后的产品门禁

现在验证的是“有操作、有风险、有资源、有长期变强”的最小核心循环。后续 2E 应针对未建造/建造、雷击/护盾、站桩/主动拾取等固定种子与真实操作进行对照，测量 3–5 分钟完成率、跨场提升和挫败点。未经决定，**不得直接把独立出击设为正式游戏默认模式**，也不得在本 PR 偷加其他大玩法。
