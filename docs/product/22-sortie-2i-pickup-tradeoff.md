# 2I-B：碎片拾取风险与手机触控容差

基线：2026-11-18，2G Draft PR #74 HEAD `ca7549831eb4658fa9e0d23c8328102e61a5e433`；2I-B 工作分支 `experiment/sortie-2i-pickup-tradeoff-20261118` 从此 SHA 创建、初始 compare 为 0 ahead / 0 behind。参考仍未合入的 Draft PR #79，避免将 16px 当成生产基线。仅新增本线专属脚本、Vitest 和报告，**保留正式候选 pickupRadius=28**；不改 `sortie-sim.js`、战技、掉落、敌伤、奖励上限、存档及其他开发线。

## 方法及可重复性

执行 `node scripts/sortie-pickup-tradeoff-2i.mjs --seeds=40 --forge=0 --assert`。参数 28/24/20/16 为单因素，**不直接写回配置**：脚本读取现有 `src/systems/sortie-sim.js`，通过 Node ESM data URL 导入原引擎，在内存里只替换 `src/config/sortie-data.js` 的 `rewards.pickupRadius`。仍使用原 `createSortie/stepSortie/chooseSortieSkill` 和原 `previewSortieRewards`，固定 60Hz、25s 战技选择、75s 结束。其余数值和官方 Run/Profile 不变。

40 个固定 seed（000–039）× D=0/40/75 × 雷/纹 × 5 种路线 × 4 半径 × 2 档预建剑台 = **9,600 场**（forgeLevel=0 和 1 各 4,800 场）。无建设版通过 `node scripts/sortie-pickup-tradeoff-2i.mjs --seeds=40 --forge=0 --assert` 重放；两档完整比较则运行 `node scripts/sortie-pickup-tradeoff-2i.mjs --seeds=40 --forge=both --assert`。固定路线：

- `kite`：原 `experimentInput` 24 秒绕场，不追碎片，作为机会成本对照。
- `pickup`：原 `experimentInput` 主动追寻最近碎片，同时在近敌 64px 内回避。
- `reverse`：每 540 tick 反向 65 tick（1.08 秒），复用 2H-B 长反向误触。
- `short-reverse`：每 240 tick 第 118–137 tick 短暂反向 20 tick（0.33 秒），模拟瞬间方向错误。
- `drift`：方向交替偏转 0.17/0.39 弧度（约 10°/22°），模拟持续手指偏移。

后四组均沿用同一个主动拾取基准移动目标；误操作只变更方向矢量，不做任何合成扣血。测试记录实际受击、剩余生命、胜场、击退、碎片数、漏拾数、可兑换碎片灵石、首次拾取反馈时间、靠近掉落时的受击、靠近敌人拾取的次数。所谓“靠近掉落时受击”仅为空间相关代理，不能直接归因于拾取。可传 `--forge=both` 重放两档剑台，但 forgeLevel=1 是**预建成场景**，非真实两场花费 6 灵石的权威经济配对结算；不能据此主张剑台 ROI。

## 判断、产品门禁及局限

1. **不采纳 16px**：高危纹误操作出现 38/40，不能以人为制造的难操作取代有趣的空间风险；该值没有真人触摸容错证明。
2. **24px 也暂不提交运行时代码**：对绕场有温和削减，对主动拾取的灵石与受击几乎无变化，尚不足以证明是更好的正式半径。
3. **20px 不构成明显的平衡最优解**：在高危长反向下受击反而下降，提示弹道接触、敌人位置与无敌帧交互非单调；不能只凭一项高危均值选参数。
4. 缩半径令绕场更迟获得首次拾取反馈，且被动擦到的碎片减少；但主动脚本依然能精确靠近掉落点。这是自动路线的能力，**不是** 320×568 真人摇杆手感证据。
5. 全部实验基于已有掉落机制、真实碰撞与奖励预览；没有修改生产引擎、真实存档或永久经济。若要真正建立风险，下一阶段需由总控评估更有意义的战斗空间约束与拾取可见性，不能让本线越界更改伤害或掉落逻辑。
