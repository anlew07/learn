# 2AG-A · 同一遭遇的玩家 / AI 控制器原型

> 基线：`main@d4c044e283c32a0d523da0cd331817168a69d855`。
> 本阶段是 2AF 的第一项技术切片，不接入正式 RunState、存档或首页入口。

## 玩家目标

同一场真实遭遇应允许两种控制来源：

- 玩家：手动走位；普通攻击仍由战斗模拟器自动完成；玩家主动选择战技。
- AI：在玩家未接管、主动交还或暂时离开时负责走位；普通攻击继续由同一个模拟器自动完成。

切换控制来源不得重置生命、敌人位置、弹道、掉落、技能冷却或战斗时钟。

## 本阶段实现

新增只读、确定性的 `getAutonomousEncounterInput`：

- 远距离接近目标，进入自动攻击射程后保持环绕；
- 近距离敌群产生排斥，避免站桩贴脸；
- 预测投射物短时间内的最近接触点并进行侧向/反向规避；
- 远离场地边缘；
- 没有近身威胁时，顺路拾取附近真实碎片；
- 所有方向归一化到 [-1, 1]，不读取随机数、不修改战斗状态。

新增 `chooseAutonomousEncounterSkill` 作为托管模式的选择策略：

- 生命较低、近身敌人较多或存在逼近弹道时，优先防御型战技；
- 局势安全时优先进攻型战技；
- 只在战斗明确等待战技选择时返回候选，不会擅自改写已有构筑。

普通攻击仍由原有 `stepSortie` 自动索敌和发射。控制器只提供输入，不拥有伤害、掉落、奖励或结算权。

## 复用与依赖判断

- 复用现有 60Hz 固定步进、自动索敌、碰撞和确定性 RNG 的 `sortie-sim.js`，不再造第二套战斗物理。
- 复用原生向量计算；本轮只需少量二维方向场，无需 A*、物理引擎或第三方 steering 包。
- 项目现有 Vite / Vitest / Playwright / Canvas 2D 足够；不增加运行时依赖。
- 参考已有 2AA 的展示/模拟分离原则：控制器不依赖 Canvas 帧率，渲染不拥有战斗状态。

## 测试

Vitest 覆盖：

- 无威胁待机、远敌接近、近敌撤离；
- 弹道规避、边界规避、低风险拾取；
- 决策确定性、输入范围和纯函数不变性；
- AI 与玩家输入在同一个 battle 对象上交替驱动；
- 40 个固定种子重复运行，结果完全一致。

## 明确边界

本阶段**尚未**把战斗接入正式主屏，也没有让正式世界每日行动产生可接管的实时遭遇。当前模拟器仍是独立试验基础；本 PR 不改变它的奖励、时长、危险参数、正式存档或世界经济。

下一阶段应把“真实排险行动 → 询问自动处理/接管 → 统一遭遇模拟器 → 一次性正式世界结算”做成单世界闭环。必须先设计可恢复的 pending encounter 和幂等结算，再开放正式玩家入口；不能只把独立试玩入口换个名字。
