# 灵灾出击 · 阶段 2C：真实双世界日结算与独立存档

> 2026-11-17 · 本变更是建立在 [2B PR #66](https://github.com/anlew07/learn/pull/66) 之上的第三层叠加 PR。**正式 main / 原正式存档不迁移；TapTap 正式玩法切换并未授权或发生。**

## 实现范围

玩家仍从单独 `?mode=sortie` 试玩入口进入。2C 新增暂停的“灵灾营地”展示：可查看灵灾灵石、经验、P/D 与废土零件、风险和当天行动。点击出击后先持久化 `pending`；完成 75 秒、0 生命或明确确认撤离，才将完整**固定 60Hz 战场输入轨迹**作为候选交给权威 `Engine.settleSortie()`。

1. **权威重放**：`src/systems/sortie-trace.js` 按独立 seed、当前灵灾危险 D、逐 tick 移动、技能选择与撤离逐项复算。只有真实结束的结局才能获奖。UI 不能向引擎直接提交“金币 999”或裸数值。输入上限、格式、异常 tick、重复技能与伪造 ID 都拒绝。回放旨在维护规则与幂等，**不是无后端情况下的反作弊承诺**。
2. **一次行动替换**：原 `Engine.step(s)` 公共语义不变；内部抽取 `tickDay(s,optionalValidatedSortie)`，仅灵灾当天“自治动作位”用一次出击代替，`recordWorldAction(...,"sortie")` 恰好一次。资源/XP/P 由 `produce / addProgress` 走既有成长、里程碑与记忆规则；同日的自然风险、事件、终局和废土真实自行行动仍照常进行。**绝不调用旧 `doAction('fight')` / `waveCombatBonus` 叠加奖励**。
3. **克隆提交与去重**：引擎先验证、再在克隆的世界快照中演化；失败不修改旧引用。记录 `sortieId` 账本和轻量校验签名，重放同一出击 ID 返回存过的回执而不多推进一天；同一 ID 换轨迹拒绝。跨世界结果包含两个世界各自的实际 XP/资源/P/D 变化与当日行动 ID；不会写死废土支援。
4. **真实落盘后才领取**：`src/services/sortie-persistence.js` 用现有 `idb-keyval` 单一原子 `set(key,snapshot)` 保存“整局双世界 + pending + 回执”，新键 `simultaneous-apocalypse-sortie-prototype-v1`，与正式的 Run/Profile 键完全分离。同一个 `createExclusiveSession` Web Locks 同源写锁用于双方互斥；无锁时只读，不允许写。
5. **中断与失败**：出击前准备状态先成功保存；刷新/崩溃留下的 pending 只恢复到**出击前**，不发奖、不推进日。写入失败后 UI 冻结、禁止发奖、显示重试，原型档读取失败或损坏时禁写、不可直接覆盖。保存成功后才显示权威 receipt；重复浏览结果只读。游戏停在营地时不自动推进世界日。

## 维持不变的内容

- 正式游戏仍是原 `src/ui.js` + `Engine.step` 日间经营与事件；这里修改引擎仅为了复用其世界日法则，普通 `Engine.step` 不携带出击重写。原两枚正式 key 和 `ProfileState` 未改，没有私自上线“主玩法大迁移”。
- 25秒临时战技二选一、击杀落物/移动拾取、失败/撤离奖励比例来自 2B。不是领取世界碎片或消耗 AP 的额外暗门。
- 仍无“护灵剑台”、建造支付、第二场攻速增强；那是 2D 独立 PR。
- 不在这个阶段增加后端、排行榜或防外挂承诺；未来如有联网改造，必须重新审查信任边界。

## 验收要点

必须以 CI 真实结果为准：日 +1，两个世界各自一次主行动；废土固定 RNG 与同 seed 的原自治对照一致；真实末日 D100/截止日不能被出击结果覆盖；奖励一次、相同和不同重放路径不会重复领；非完整战斗和异常轨迹拒绝且不变更；失焦冻结、刷新回退、单键原子存档拒写与恢复、正式两键字节不变、多标签锁互斥、原正式 Vitest/Playwright/构建不退化。手机 320/390/430 视口须展示两世界真实差额，不用内置假数字。
