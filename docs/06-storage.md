# 06 · 局内状态与存档

## 数据分类

- Definitions：静态配置及稳定 ID，运行中不能被 UI 修改。
- RunState：runId、当前游戏日与阶段、世界集合、灵魂/AP、活动事件、经历/威胁/状态、随机流、结算状态和近期日志。
- ProfileState：本局之外的碎片、升级、世界/天赋解锁、历史结果。
- Settings/Analytics：速度、暂停设置、测试与统计。

每世界 WorldState 至少包含：worldId、状态、deadlineDay、P/D、等级经验资源、策略、当前行动目标、经历标记、事件实例/冷却、持续威胁、特殊机制、终局状态、独立随机状态。

## 可复现性

每局生成根种子，并给每世界独立随机流及全局随机流；保存每条流当前状态。相同规则版本、种子和玩家操作顺序，应得到一致结果。避免某世界多触发事件就改变其他世界的随机序列。

## 本地保存

**V0.2 alpha 实现：** 已采用浏览器 IndexedDB（idb-keyval），不再使用早期计划的 localStorage。通过 `src/services/persistence.js` 的 `getMany/setMany` 在一次原子事务中保存**本局RunState + 永久ProfileState**；按操作生成快照并串行保存，避免旧异步写入覆盖新状态。重要日结算、玩家操作、暂停、世界结局及页面隐藏会发起保存。保存失败将出现可见警告并在后续操作中重试。

**已实现**本局结算的 `run.rewarded` 标记和世界状态检查；**仍待实现/补测**完整玩家指令operationId去重、多标签页锁、完整快照备份/回退与手动JSON导入导出。不要把这些旧设计任务写成当前已完成的功能。不同浏览器不会自动同步存档，清理浏览器数据仍会造成丢失。

## 兼容策略

**开发早期以快速调整为先**：允许明确告知后重置早期测试存档，不为尚未发布的原型维护复杂旧版兼容。正式公开版本再确定迁移承诺与兼容流程；现阶段保证设计上区分游戏版本、存档 schema 版本、数值版本即可。

一局中途更新规则需要明确如何处理：保持本局规则快照或提示重开，不能偷偷混用新旧数值。发现损坏存档先尝试有效备份，不静默清空。

## 跨世界状态的存储边界

SoulLinkState 保存：每来源世界成功广播次数、已广播 memoryKey 和上次广播日；每目标援助 nextEligibleDay（P与D共用）；全局融合 nextEligibleDay；已发放和已消费的世界回响；已处理 operationId 与结算签名。提供者的未来3日虚弱效果以 world.statusEffects 保存，不新建独立战斗等级。所有援助及融合需原子提交双世界变化、AP/魂、冷却和目标事件实例结果。详见[双世界联动内容包01](../content/packages/soul-link/01-dual-world.md)。
