# 06 · 局内状态与存档

## 数据分类

- Definitions：静态配置及稳定 ID，运行中不能被 UI 修改。
- RunState：runId、当前游戏日与阶段、世界集合、灵魂/AP、活动事件、经历/威胁/状态、随机流、结算状态和近期日志。
- ProfileState：本局之外的碎片、升级、世界/天赋解锁、历史结果。
- Settings/Analytics：速度、暂停设置、测试与统计。

每世界 WorldState 至少包含：worldId、状态、deadlineDay、P/D、等级经验资源、策略、当前行动目标、经历标记、事件实例/冷却、持续威胁、特殊机制、终局状态、独立随机状态。

## 可复现性

每局生成根种子，并给每世界独立随机流及全局随机流；保存每条流当前状态。相同规则版本、种子和玩家操作顺序，应得到一致结果。避免某世界多触发事件就改变其他世界的随机序列。

## 本地保存

首版基于浏览器 localStorage：主存档 + 上一有效备份 + 临时保存；写入完整快照，验证后替换；保存时机为每个日终、关键操作、暂停/切后台、结局与局外购买。提供 JSON 导入导出。不同浏览器来源不会自动共享存档；浏览器清缓存有丢失风险。

重要指令、事件实例、世界终局及本局奖励均需唯一 ID 和结算标记，避免刷新重复扣费、重复发世界回响和重复碎片。

## 兼容策略

**开发早期以快速调整为先**：允许明确告知后重置早期测试存档，不为尚未发布的原型维护复杂旧版兼容。正式公开版本再确定迁移承诺与兼容流程；现阶段保证设计上区分游戏版本、存档 schema 版本、数值版本即可。

一局中途更新规则需要明确如何处理：保持本局规则快照或提示重开，不能偷偷混用新旧数值。发现损坏存档先尝试有效备份，不静默清空。
