### 可验证结果与不可验证结果

自动化只验证**可观察的游戏反馈及存档数据的一致性**：碎片拾取的 UI 数字与结算回执相等；“击退每 3 个敌人生成 1 碎片”所生成碎片总数应等于拾取与未拾取之和。这**不自动证明玩家一定能拾到碎片**，也不证明拾取风险设计合理（由 2H-B 实验负责）。技能提示包含 4 秒雷和 25 秒阵纹，但文案是否能被新玩家理解仍需真人观察。剑台实际胜率收益由 2H-C 实验负责。

小游戏设计的 75 秒单场不能代表真实体验只需 75 秒：进入营地、看懂目标、决定建设、重新出击的 3–5 分钟总路径应由观察员计时，记录卡点、主观理解与误触。Playwright 使用虚拟时钟，不应填造真人时长。

## 设计风险（不在本分支修改）

1. `src/sortie.css` 对通用按钮设置 `min-height: 42px`，低于常见 44 CSS px 触摸目标参考值；小屏的两枚操作按钮可能需要真机实测误触率和单独 UI 修正。
2. 320×568 的部分营地内容位于可滚动区域，自动化可验证程序滚动可达，不能确认首次玩家会主动下滑看到剑台和关键解释。
3. 存活并结算不代表玩家理解“灵石兑换上限 2/2”“战技一次选择后的实战收益”或放弃剑台的机会成本；建议真人 A/B 口述目标与决策理由。
4. 如 2H-A/B/C 改动进攻、拾取或建设参数，需要本 PR 合入前按最新 **2G+2H** 集成候选重跑；不可把单独的 2G 基线通过推导为联合通过。
