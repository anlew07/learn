# C 线 QA：首次玩家路径基线与可用性验收（2026-11-16）

> 基线：`main@b665d9e3bb29942339ce636de20682f58aaee226`。这是**代码/既有浏览器测试核对与待执行试玩方案**，不是未经说明的真人测试结果。A 负责视觉与布局，B 负责教学与玩法表达；C 不修改其实现文件。

## 第一次开局的十个检查点

“页面现状”来自本次对 `src/ui.js`、`src/engine.js`、现有 `e2e/user-flows.pw.js` 的核对。所有“能否理解”的最终结论均为**待真人验证**。

| 关口 | 新玩家应该知道 | 当前 main 提供了什么 | 理解障碍 / 多余操作 | 下一步是否可找到 |
| --- | --- | --- | --- | --- |
| 1. 首开首页 | 我是多个世界的共同决策者，目标是尽可能救援并取得局外资源 | 顶部宣称“守护三个世界”，首局按钮“快速体验/深入模式”，旅程档案显示碎片 | **高风险：**第一局实际只有两世界；快速体验起始又仅展示一个，且首页未直接解释两局后解锁兽王 | 有“开始第1局”，但完整/聚焦差别不充分 |
| 2. 进入第一局 | 分身自动行动，玩家应看日数、P、D、AP、倒计时 | 快速体验有 P/D/AP 简介；世界卡有当前目标/行动；初始暂停 | “分身”和“灵魂”与操作层次需教学串联；首页没告诉玩家初始暂停 | 有“继续模拟”，调试版另有“+1天” |
| 3. 第一次自主推进 | 一天后发生什么，资源/成长/风险如何变化 | 1×默认20秒/日，按键继续才开始计时；世界卡记录“正在进行”、后续可展开自主判断 | **高风险：**首次反馈可能要等待20秒；无明显“预计下一次动作”节奏说明 | 可以继续推进，但等待时可能以为卡住 |
| 4. 辨认两个世界 | 灵灾与废土各有目标、P/D/资源、自己的策略与倒计时 | 深入模式两张世界卡；聚焦模式到第9天才自动展开，或手动跳过 | **高风险：**聚焦期隐藏第二世界及整个底部导航；尽管它仍真实推进，玩家可能误认为没有第二世界 | “立即进入深入模式”可以跳过；未跳过前跨世界入口不可达 |
| 5. 切换自主策略 | 策略改变未来自主行动偏好，前3天免费，第4天起1AP | 各世界卡“长期策略”选择，费用/禁用原因依据合同显示 | “成长/排险/救援优先”不是直接立刻执行行动；策略代价与效果仍待初玩验证 | 在世界卡下方能找到；作战情报为折叠内容 |
| 6. 首个重大事件 | 可以比较概率、默认后果和成本，不手动选择也会到期结算 | `.event` 显示“不操作的结果”、概率和合法选项、截止日 | 随机触发的首个事件时机不可保证；若玩家错过，需要战报说明后果 | 活跃事件在相关世界卡后；聚焦时另一个世界事件能否被及时感知需人工检查 |
| 7. 首次战斗与战技 | 战斗是分身自动作战；战技三选一会影响后续构筑；重播不再结算奖励 | 可见战技觉醒面板、三波战报、重播说明及统计 | 不应暗示玩家可实时操作；首次战斗/觉醒出现时机不确定，提示与反馈可能隔得太远 | 有战技选项与世界内战报，需真人判断是否易发现 |
| 8. 第一次跨世界援助 | 由哪个世界提供材料，改变哪个世界 P/D，消耗4材料/1AP/1灵魂并有冷却 | “灵魂联结”页面预览实际增量、费用、目标冷却，点击后确认弹窗 | **高风险：**聚焦模式底部导航隐藏，玩家此时无法尝试援助；“万我同源/灵魂联结”是否可理解待测 | 深入模式的底部导航可达，跳过聚焦无资源损失 |
| 9. 观察世界结局 | 单个世界可成功/失败，两世界都结束后进入总结果 | 世界状态卡、运行完成后的“本轮救援行动已结束”和成功数/碎片 | 总结果只给数字，是否能理解失败原因、是哪次决策导致的，需要结合战报实测 | “查看本局经历”可达 |
| 10. 结算与下一局 | 本局留下碎片、局数、收藏进度；下次可以重试不同策略，第三局加入兽王 | 结算页有“开始下一次穿越”；首页旅程档案统计碎片与局数 | **高风险：**当前**没有正式的永久属性升级系统**，不能把“获得碎片”描述成已能购买强化；下一局的不同点提示偏弱 | 可以开下一局，但局外成长的价值待验证 |

## 快速真人试玩任务（不提供说明书）

让没有读过项目文档的试玩者在手机打开非调试版；只给出下面六项任务，不解释玩法机制。每项记录“独立完成 / 提示后完成 / 未完成”、用时、误触、玩家原话及证据。**不招募到真人就全部标记为未验证。**

1. 在开始操作前，说出本局目的以及怎样判定成功。
2. 同时看到多个世界后，指出风险最高的世界并说出判断依据。
3. 指出“分身会自动做的事”和“我主动决定的事”，实际完成一次推进。
4. 修改一个世界的策略，说明它是即时行动还是长期倾向、是否消耗 AP。
5. 遇到事件/战斗后，找到真实结果和战报；至少完成一次合法跨世界援助。
6. 完成结算后解释失败或成功原因、获得的碎片能做什么、下一局可以改变什么；如果玩家认为可用碎片升级，记录为**误解**而非测试通过。

建议可用性门槛（**预先定义的产品验收建议，并非已经通过**）：
- 任务1、2、3、4、5、6 每项至少80%的首次试玩者可无提示完成；首局主目标与风险判断必须正确，不能只统计按钮点击成功。
- 对操作性路径要求 **0 处阻断**（在允许的正常玩家操作下可以完成），若临时触发随机性不足，应在下一局或测试情境继续，不用测试作弊冒充人类理解。
- 每条困惑必须归到具体页面、术语、操作步骤与播放器截图/录像；记录玩家原话，不用 QA 猜想代替数据。

## 自动化与人工的清晰边界

新增 `e2e/first-player-acceptance.pw.js` 使用**当前 main 已存在的** `data-action`、`.world`、`.event` 等选择器，验证：快速体验、跳过但两个世界持续模拟、策略合同、援助扣费、事件选项、真实引擎生成的终局、战技/战报、四种宽度的导航可达性与重载存档。测试中的事件和战技情境**明确注入合法状态**以避开随机触发时机；它们不等于“首次玩家自然会看见”。

存档与竞争安全无需重复实现：`e2e/user-flows.pw.js` 验证多标签 Web Locks 接管，`e2e/storage-boundaries.pw.js` 验证 IndexedDB transaction abort，`e2e/storage-recovery.pw.js` 验证保存失败、恢复拒写，`e2e/mobile-runtime.pw.js` 验证后台与定时器。CI 中全部原有用例仍须继续跑。

待 A/B 合并后再对**真实新界面**重新量测：一级信息层级、看见两世界的方法、词汇解释、事件前后反馈、手势安全区；新的 DOM 选择器须从新实现查证，禁止臆造或暂时跳过失败断言。

## 对 A / B 的待办反馈（不越界修改代码）

- **A / B 联合，P1：** 首页“三世界”、首局“两世界”、聚焦“一世界”应统一解释解锁规则；提供清楚的“当前第几世界/为什么只看到一个”。
- **B，P1：** 自动行动/玩家主动决策应在首次30秒可区分；当前1×20秒的静止期需要看得懂的第一步反馈。
- **A，P1：** 聚焦期间隐藏跨世界导航属于刻意简化，但“查看更多/立即跳过”的语义必须让玩家知道还有两个世界在运行，不要误认为资源被停用。
- **B，P1：** 结算显示“得到碎片”与“永久升级未实现”的界限；避免许诺还不存在的局外强化。
- **A，P2：** 重大事件、战技觉醒与战报应在视觉上明确分区，不把“自动战斗回放”误排成实时操作。
- **C 集成门槛：** A/B 进入 main 后对照上述六项真人任务重新打分；以新 DOM 修正测试，但不能把文字变化视为用户理解已经通过。
