# 01 · 核心架构

## 三层模型

- **通用引擎**：日历、时序、随机数、自动行为决策、效果提交、状态管理、世界结果、日志、存档。
- **世界规则**：每个世界的成长体系、专属机制、可用行动、持续威胁和末日目标。
- **世界内容**：怪物、地点、事件、主线、分支、机缘和文案。

UI 只发送命令，不直接更改局内数值；游戏状态是唯一可信来源。静态内容定义只读，局内状态独立保存。

## 逻辑模块与边界

| 模块 | 职责 |
| --- | --- |
| GameEngine | 统一日初、日终和运行状态 |
| DecisionSystem | 根据策略、需求、危险、经历、行动惯性选择合法动作 |
| ActionSystem | 验证玩家操作和费用 |
| EffectSystem | 统一检查/提交数值、标记和持续状态变化 |
| EventSystem | 候选池、权重、独立实例、期限和自动结果 |
| ThreatSystem | 持续灾源、清剿进展和每日影响 |
| ProgressionSystem | 经验、成长阶段、突破和经历 |
| FinaleSystem | 主线准备、最终行动、独立结局 |
| SoulLinkSystem | 记忆、资源援助、灵魂叠加、回响 |
| StorageManager | 保存、读取、恢复、完整性检查 |
| UIManager | 首页、观测、世界详情、事件、结局和升级 |

上述为逻辑隔离，未来实现时可在文件层合并，但不能互相私自结算同一件事。

## 可扩展内容

每个世界声明自己的 actions、growth、enemies、threats、events、story、special、finale 和 soulContribution。统一的条件系统支持：数值比较、世界状态、标记、时间、行为、状态以及 AND/OR/NOT。效果系统支持：数值增减、资源消耗、增删状态、添加标记、解锁行动/事件、排定后续事件、发送共享记忆、请求结局检查。

未来新增功法/事件优先增加配置；新增世界优先复用接口；不能表达时才提议引擎变更。

## 通用日常行为

成长、采集、战斗、探索、拯救五类。玩家选择成长/清剿/拯救三种长期策略，分身自行决定每日具体动作。选择过程：筛选合法动作 → 评估策略偏好、当前需求、机缘、惯性与风险 → 选择一个主要动作 → 交 EffectSystem 提交结果。没有合法高价值动作时仍要有低风险保底行动。

## 世界之间的隔离

世界有独立随机流、进度、事件、灾源与结局。跨世界变更只能经过 SoulLinkSystem；世界内容不得直接访问另一个世界的专属字段。跨世界被动记忆在所有世界当日日常结算完成后统一发放，避免世界数组排列影响结果。
