# 05 · TapTap H5 竖屏交互

## 核心五界面

1. 首页：开始/继续、局外成长、存档入口。
2. 模拟主界面：全局日期、灵魂、AP、速度、暂停、三个世界状态卡、紧急事件、近期战报。
3. 世界详情：成长、拯救、经历三个标签；策略、资源、状态、专属机制。
4. 结算：每世界结局、关键经历、碎片、下一次模拟。
5. 局外成长：永久升级、解锁世界、天赋。

顶部固定全局状态，底部保留世界/事件/灵魂/日志入口。主界面纵向排列世界卡，每卡展示 P、D、剩余时间、当前行动及风险；重要详情可展开。

## 重大事件

列表按紧迫程度排序。进入详情时临时冻结模拟计时；关闭后恢复先前是否暂停的状态。呈现自动处理结果、手动选项与成本、剩余处理游戏日。按钮条件不足时显示原因。没有处理的事件照样按到期规则自动执行。

## 万我同源

在“灵魂”面板显示记忆记录、资源援助、二人/三人之力和世界回响。资源援助流程为：选择来源 → 目标 → 效果 → 显示完整成本 → 确认。借力必须说明来源世界后续虚弱。结果显示具体前后数字和一段短战报。

## 文字反馈与可读性

常规日志合并，突破/机缘单独突出，世界危机与结局置顶。玩家始终能看见当前目标、缺什么材料、为什么进度已满仍无法拯救。

设计目标：正文字号 15–16px、主要按钮高度至少 44px、手机宽 320–430 CSS px、无横向滚动、底部安全区域适配；这些不是平台强制标准。

## 新手

第一次固定灵灾+尸潮双世界。第一次事件或援助可分步引导，其余模拟仍自动运行。第二局开放二人之力，第三局加入兽潮三世界及三人之力。教学可跳过，不强制玩家点击每日行动。

## 强制美术规范（不可降级为建议）

游戏所有可见 UI 与美术资产必须使用统一的 **2D 像素风格**，覆盖首页/主界面、三世界场景、角色、敌人、技能图标、按钮、导航、边框、面板和装饰。整体参考经典像素 RPG 与像素生存游戏的视觉语言，不允许某个页面或资产单独转成其他画风。

- **像素网格统一：** 图标、角色和场景使用明确的整数像素网格；放大时采用最近邻/像素化显示，边缘保持清晰，不出现意外抗锯齿或半像素模糊。SVG 使用 `shape-rendering="crispEdges"`，CSS 可使用像素块、阶梯边框和硬边阴影。
- **有限色板：** 建立全局基础色与世界专属强调色，控制单张素材的颜色数量；用明度、轮廓和图形共同区分状态，不只靠颜色表达。按钮、面板、场景和角色必须共享同一套色彩逻辑。
- **明确禁止：** 写实插画、照片质感、3D 渲染、玻璃拟态、磨砂模糊、霓虹渐变科技风，以及与像素 RPG 不协调的混合风格。界面主视觉使用平涂色块和清晰边框；避免渐变、模糊滤镜、柔光和玻璃高光作为装饰手段。
- **文字例外：** 不要求中文文字像素化。正文和长文案优先使用清晰的系统字体，保证字号、行距、对比度和换行；像素字体仅可用于短标题或数字，且不得损害可读性。
- **移动端优先：** 先按手机竖屏设计，覆盖 320–430 CSS px；关键操作触控区至少 44px，底部导航适配安全区，无横向溢出，信息层级清楚。减少不必要动画与大面积滤镜，控制低端设备 GPU 开销。
- **资源约束：** 优先轻量 SVG、CSS 绘制和可替换精灵图；不为了画风引入大型框架、游戏引擎、远端图片或不必要字体。素材应有统一命名、网格、色板和独立目录，方便整体替换。

### 验收门槛

- [ ] 主界面、三世界、角色/敌人、技能、按钮、边框和装饰没有明显画风混搭。
- [ ] 像素素材按整数网格绘制与缩放，轮廓清楚，色板受控。
- [ ] 不存在写实、3D、玻璃拟态、模糊渐变科技风等冲突视觉元素。
- [ ] 中文正文仍清晰易读；不以像素字体强行统一所有文本。
- [ ] 320–430px 竖屏布局、44px 触控目标、安全区和低性能设备均得到考虑。
- [ ] 素材体积、CSS 效果和动画开销受到控制。

此规范优先于本文中任何早期的视觉实验描述；若旧 CSS 或旧素材与此冲突，后续 UI 美术迭代必须逐步替换，不得以“历史样式”作为保留冲突风格的理由。
