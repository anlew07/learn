# 像素美术语法 v1 · 2026-11-16

## 视觉目标与不可突破的边界

第一参考《贪婪地牢》手机版的**轮廓、材质分层、操作反馈**，第二参考 Shattered Pixel Dungeon 的**图标、边框和信息优先级**；只学习设计方法，不临摹角色、地形、界面或商标。禁止恢复 `sgravoquest-assets` / Tiny Dungeon 旧素材。

本规范服务于 TapTap 手机竖屏 **固定游戏 HUD + 有状态的地图**，不是长卷网页。场景首先说明“世界处于什么状态、分身正在做什么、哪里有危险”，然后才考虑装饰。

## 统一基础语法

| 元素 | 规则 |
|---|---|
| 颜色 | UI 中性色为深墨 `#111b21`、石灰 `#343b36`、高台 `#4d5548`、暖描边 `#9b9277`、羊皮文字 `#f3e8cc`。一屏仅使用一种主行动强调色。 |
| 世界点缀 | 灵灾青玉 `#92c8b1`、废土赭金 `#d2a76b`、兽潮灰玫瑰 `#d9a1a0`。颜色不可代替危险数字或文字。 |
| 边框 | 2px 外描边 + 内侧 2px 亮面 / 暗面阶梯；0 圆角、无模糊玻璃、无柔和阴影。弹窗外轮廓可 3px。 |
| 按钮 | 默认石质凸起；主行动苔绿；待决策赭色；按下下移 1px 且内凹；禁用保持文字可辨而不是消失。 |
| 图标 | 推荐 16×16 或 24×24 逻辑格，2px 轮廓，大色块优先。不可直接把 emoji 作为最终美术资产。 |
| 人物与威胁 | 当前 48×64 分身是临时比例基准；头、武器、背包、角形成各自独立轮廓。16px 缩略图必须重新绘制，不能直接缩小大图。 |
| 地图 | 后景（天空/远山）→ 中景（树/建筑）→ 地面材质 → 可交互主体 → 前景遮挡/危机信号。没有状态驱动的纹理不应喧宾夺主。 |
| HUD | 顶部日数与资源、世界切换、地图、危机/准备度、底部操作、内部滚动抽屉；信息优先级固定。 |
| 字体 | 中文系统字体优先，靠粗细、对比和 1px 深色文字投影强调像素质感，不擅自加入大体积点阵字库。 |
| 动效 | 仅装饰、不得推动游戏状态；现有帧率上限和减少动态效果偏好必须保留。 |

## 代码与资源归属

- `src/stage-shell.css` 保留布局与触控安全区；`src/pixel-art-language.css` 管统一 token 和组件材质，只在 `stage-mode` 的游戏屏作用域下生效。
- `src/ui/pixel-stage.js` 管层级顺序与 Sprite 装载；`src/ui/world-scene-details.js` 管可观察世界状态表现和世界视觉地标，绝不能调用引擎。
- `src/assets/original/{character|creature|prop}-{world}-{name}-v1.svg` 为后续新增资源推荐命名；现有四张已上线引用的文件保持旧名，以免破坏路径。未来单个素材同时提供缩略版时追加 `-icon`，不靠缩小主图。
- 禁止引用外部 CDN；图片优化应检查像素对齐、深浅轮廓、体积和低分辨率识别度。新资源登记作者、来源 URL、许可证版本、修改情况与文件清单。

## 资产审计

- 当前四张 SVG 为本项目独立原创（沿用 PR #51），没有授权给第三方或导入外部素材；本次新增为 CSS 与 Canvas 几何绘制，亦无第三方图片。
- 已核对 [0x72 DungeonTileset II](https://0x72.itch.io/dungeontileset-ii) 为 CC0 的 16×16 地牢资源，但角色在当前大地图比例下偏小；[Pixel Frog Pixel Adventure](https://pixelfrog-assets.itch.io/pixel-adventure-1) 为 CC0，却采用横版透视。**两者不导入，不将“免费”视为符合审美**。
- 任何未来购买/授权的外部包须单独核对实际下载文件授权，不能根据作者其他包推断相同许可。

## 视觉验收门槛

1. 320×568、390×844、430×932：主屏无横纵主页面滚动；地图、状态数字、主要按钮与抽屉关闭入口可见。
2. 对照同一个种子与三态 stable / critical / restored 截图；地面与门洞变化需要一眼可见，不能只有文字改变。
3. 角色、同伴、角兽和箱子按真实手机尺寸看图；如果缩小后不能区分，要改轮廓，不是加装饰性粒子。
4. 检查 `prefers-reduced-motion`、高对比度、无鼠标触摸操作以及 save/load 后视觉派生不改变游戏状态。
5. 用 Playwright 截图和真实 Android/iOS WebView 二次核对。自动化通过仅代表技术回归，**不代表达到参考游戏的商业美术质量**。
