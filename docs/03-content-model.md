# 03 · 内容模板与剧情分支协议

## 内容结构

- World：背景、初始资源、成长集、行动集、事件池、末日参数、主线、专属机制、联动贡献。
- Action：类别（成长/采集/战斗/探索/拯救）、合法条件、决策评分、基础效果、风险、事件池。
- Growth：阶段 ID、名称、经验/材料门槛、自动突破、解锁和共享标签。
- Enemy：普通/精英/首领、出现条件、要求战斗等级、胜负效果、首次经历。
- Threat：持续威胁节点、强度、清剿进度、每日压力、清除效果。
- Event：来源、条件、权重、次数、冷却、自动选择、人工选择、唯一实例。
- Branch：条件、选择、即时效果、经历标记、后续关联。
- Status：对象、开始日、到期、修正、叠加与清理。
- Finale：基础资格、准备、挑战、成功/失败与冷却。
- SoulLink：来源/目标、参与条件、成本、一次性效果、共享/冷却。

模板示例参见 [content/templates](../content/README.md)。

## 分支设计

**事件不是固定日期播放的长剧本。** 行动可能发现事件，世界环境也能自主触发事件。发生后选择将写入“经历标记”，后续事件依条件开放。普通事件只影响即时数值，重要事件留下标记，关键事件改变终局方案。

使用“分支 → 差异 → 汇合”的结构，避免分支指数爆炸。示例：灵灾发现古碑 → 稳妥研究获得古阵认知，或冒险激活承担灾害风险 → 共同进入封印主线，但拥有古阵认知者可以选材料较少的方案。

## 标记归属

- 分身经历：战斗感悟、修炼路线。
- 世界经历：已定位母巢、已找到阵眼。
- 全局本局经历：首次双魂共鸣。
- 局外永久解锁：已解锁的世界、升级和天赋。

标记使用稳定 ID；不能通过日志字符串判断是否完成任务。新增分支不得让没随机抽中机缘的玩家陷入必败死锁。

## 事件规范

必须同时具备模板 ID 与实例 ID。当前世界同一时间最多有一个等待玩家干预的重大事件。普通事件自动结算；重大事件到期自动处理。结果效果需统一验证后提交，不能先扣行动点后因为条件失败而不发收益。

## 主线里程碑和终局方案

非随机主线里程碑可由 P/等级/故事标记触发；它只解锁地点与记录关键叙事标记，不重复奖励 P，也不占重大事件槽。首次触发与存档恢复均须幂等。随机机缘、精英线索不得成为基础主线唯一完成条件。

终局方案分别声明：P、实际等级、必要标记、可用资源、是否需要战斗、成功与失败处理。**不能强制所有世界的最终行动都有 Boss 战**：灵灾可采用稳定条件型封印，而尸潮、兽潮可以配置战斗型终局。

## 内容生产的最小门槛

每次新增事件至少记录：为什么出现、默认会怎样、玩家能否干预、即时结果、持续状态、后续关联、与哪些现有内容相容、可能影响哪些存档字段，以及一个正向和一个异常测试案例。

**原则：** 先少量内容做出前后因果，不追求每世界固定六事件/三路线等人为数量目标。

## 可选战潮内容模板（实验）

WaveEncounter 依附**已有**Action或Event/Finale的唯一实例：waves（默认三段演出）、敌潮压力档、构筑的清潮效率与损失缓解、原本的唯一战利品来源。战技与强化选择为世界运行状态里的本局配置，每世界2攻击+1辅助、最多3次候选（暂定）；独立于重大事件槽，不要因三波造成三倍XP/三次主要行动或三次融合。Boss有效战斗Lv及终局基础资格仍采用原本规则。见[战潮模拟实验包](../content/packages/combat/01-survivor-waves.md)。
