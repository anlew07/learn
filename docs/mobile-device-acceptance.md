# Android Chrome / iOS Safari 真机验收清单（待执行）

本文件是**操作清单，不是验收结果**。Chromium 的 Playwright 移动视口只覆盖自动化环境，不能替代真实 Android/iOS 手机。对本清单任何项目，都需记录设备型号、系统和浏览器版本、测试时间、执行者、结果（通过/失败/未执行）及复现视频或截图。首版不支持跨设备自动同步。

## 准备

1. 打开正式部署的 `https://anlew07.github.io/learn/`，确认 HTTPS、状态码 200、无缺失静态资源；注意 PR CI 通过不等于主线 Pages 已更新。
2. 在设备上打开开发者工具远程调试（Android Chrome DevTools / iOS Safari Web Inspector），观察控制台异常、IndexedDB、Network 和页面内提示。保留已有玩家存档时禁止先清空站点数据。
3. **使用单独的测试浏览器配置/测试设备**做清除存储、无痕、容量不足等破坏性场景，不要使用玩家真实档。若不具备可控环境，标为“未执行”，不可模拟通过。

## 每个平台逐项操作

| 编号 | 实际操作 | 期望结果 |
| --- | --- | --- |
| M01 | 首次打开，创建双世界新局，点一次“推进一天”，确认保存，再刷新 | 日数与 AP/灵魂/世界状态一致；刷新后默认暂停 |
| M02 | 连续快速点击手动推进与援助/策略操作，跨刷新核对结果 | 无崩溃、不出现重复扣费、事件/援助不会结算两次 |
| M03 | 打开同源第二标签，尝试推进，再返回第一标签推进 | 第二标签只读、不能写入；首标签存档正常 |
| M04 | 关闭首标签；第二标签点击“重新取得控制权并读取最新存档” | 先重读最新日数，再恢复可写；没有旧快照覆盖 |
| M05 | 运行状态切出 App 或锁屏 1–3 分钟，再返回 | 变为暂停；不会因为后台计时一次跳过多天 |
| M06 | 暂停后关闭/系统杀掉浏览器进程，重新打开 | 已完成写入的操作可恢复；不能保证被系统杀死前尚未落盘的操作 |
| M07 | 游戏中改变横竖屏、地址栏展开/收起、系统字体大小 | 无横向溢出，按钮可触达，底部导航不遮挡操作 |
| M08 | 开启深色/浅色系统主题并调节辅助功能文字放大 | 文本、输入框、弹窗清晰可读，触摸目标没有被遮挡 |
| M09 | 在隔离测试环境拒绝 IndexedDB 或模拟存储额度不足 | 明确显示失败；读失败不可创建新局覆盖原档，写失败暂停且可重试 |
| M10 | 在隔离测试环境注入不兼容版本/损坏快照后重开 | 留存原数据并拒绝写入，显示恢复失败；不可静默初始化 |
| M11 | 使用无痕模式打开，保存后关闭所有无痕页再重新打开 | 如数据被浏览器清除，应说明无痕存储不可作为可靠长期存档；不标记持久化通过 |
| M12 | 在低端设备运行 30–60 分钟，反复切换世界/战报/战斗回放 | 记录内存、掉帧、耗电和页面崩溃；运行时间越长不应持续累积明显卡顿 |
| M13 | 在弱网、离线和重连状态重新打开已经缓存的页面 | 记录是否可加载；当前没有承诺 Service Worker 离线首启，不把离线加载失败误判为存档丢失 |
| M14 | 分享入口/从 TapTap H5 容器进入游戏，重复 M01、M04、M05 | 重点核对 Web Locks 可用性、IndexedDB 权限和返回 App 后的恢复行为 |

## 自动化边界

GitHub Actions 的 `npm run test:e2e` 以真实 Chromium 运行 390×844 触摸视口，验证单写锁/刷新/权限拒绝/损坏存档/失败重试，以及以模拟 `visibilitychange` 检查后台暂停逻辑。**无法证明 iOS Safari 后台杀进程、容量压力、真实 WebView 和长时间性能**；这些属于以上真机项目。


## 第二阶段：按设备执行与证据记录

以下为**待执行流程**，不表示已经通过真机验收。每个平台（Android Chrome、iOS Safari、TapTap 内嵌 WebView）应分别记录设备、系统、浏览器及容器的完整版本，不能混用结果。破坏性测试必须使用独立的空白浏览器配置或测试设备，切勿删除真实玩家存档。

1. **基础与恢复**：执行 M01、M02、M05、M06。启动并推进两天后刷新；继续模拟 20 秒后切后台/锁屏 1–3 分钟，再恢复。确认只暂停、不追赶补算，也不重复发奖励。强杀后只承诺**已落盘**记录恢复，不承诺未完成的异步事务。
2. **多标签接管**：执行 M03、M04。打开两个同源标签，第二页应只读；反复尝试取得锁不能夺取首标签；关闭首标签后第二页接管并**先重读**最新日数。重复三次。TapTap 不同容器可能使用不同存储分区，记录是否同源、同 WebView，不能错误推断为锁失效。
3. **可视和触控**：执行 M07、M08。纵向检查 320、360、390、430 CSS px（记录实际设备等效宽度），横屏，系统文字 125%/150%，底部手势安全区、地址栏展开/收起、系统确认框的确认及取消。分别打开世界、灵魂和战报页并完成真实触摸操作。
4. **异常环境**：在空白测试档执行 M09、M10、M11。记录 Web Locks / IndexedDB 的权限状况；额度不足或读取拒绝必须有用户可见提示，不能静默重置；无痕模式的关闭后丢档应如实标记为浏览器限制，不能算持久化通过。
5. **长时与发布**：执行 M12–M14。在低端设备连续玩 30–60 分钟，记录开始与结束游戏日数、是否意外跳天、内存/卡顿/温升/电量变化（如可测）、页面异常、刷新恢复；同时记录线上 HTTPS URL、main SHA、对应 Pages workflow run ID 和静态资源 404 情况。

### 自动化结果不能代替的项目

`e2e/mobile-runtime.pw.js` 利用 Playwright Clock 模拟长时间流逝，仅检验计时逻辑和状态，不是实机长时性能/耗电测试。`e2e/storage-boundaries.pw.js` 使用 Chromium 真正的 IndexedDB transaction abort，不能等同 Safari/iOS 的系统低存储实验。请在取得设备和实测证据后再关闭 Issue #4。
