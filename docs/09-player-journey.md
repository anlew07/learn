# 09 · 从第一局到结算：可玩原型体验流程

**版本 0.1 · 2026-11-12 · 设计+代码对应规格**。当前 \`src/\` 已开始实现；此文档只描述原型包含的行为和待改进方向。所有时间与胜率数据未完成真实玩家验证。

## 玩家体验路径

| 时段 | 模拟器做什么 | 玩家需要做什么 | 战潮实验开启时 |
| --- | --- | --- | --- |
| 首页 | 选择本局模式并建局；第一局灵灾+尸潮，第三局加入兽潮 | 开始游戏、可开关战潮 | 固定本局开关，不中途改模式 |
| 初期 | 两分身自动修炼/搜刮/调查，毁灭自然增加 | 可调整长期策略 | Lv2提供首次可选战技构筑 |
| 中期 | 普通敌人、持续威胁巢群、精英候选 | 关注重要事件、决定是否援助 | 清剿有三波式文字战报，不增额外日数 |
| 转折 | P30/65/100里程碑、重大机缘、境界突破 | 可以闭关、选择更稳妥或冒险 | P65再获得可选构筑机会 |
| 后期 | 独立准备最终封印/母巢/兽王 | 关键时刻可借力（第二局开始） | 精英首胜可能获得第3次构筑 |
| 世界结束 | saved/failed单独终止、不冻结其它世界 | 可以使用一次性世界回响 | 已结束世界停止战潮和构筑 |
| 本局结算 | 世界碎片、结果记录、后续模式解锁 | 开下一局 | 不为战潮构筑发额外保底碎片 |

## 玩家操作预算（实验约束）

1. 一般日常行动零点击，策略切换按需要进行，不作为每天必做操作。
2. 重大事件不要求点击：默认自动处理，但关键战斗可通过二/三人之力干预。
3. 战潮构筑首版**每世界最多3次**，无操作自动选择，不卡游戏；两世界最高6次，三世界最高9次，实际取决于到达里程碑与精英。
4. 三波战斗占用本次原有行动/重大事件的同一结算，**不新增3日/3次掉落**，关闭战潮后世界规则仍完整。
5. 用户主动打开剧情详情时建议暂停时钟；4×高速下首次出现重大事件可自动提醒/暂停（目前部分UI行为仍待完善）。

## 两种模式如何比较

| 指标 | 基线纯模拟 | 战潮增强（实验） |
| --- | --- | --- |
| 主要行动 | 每世界每游戏日1次 | 相同 |
| 关卡与地图 | 无实时移动 | 相同 |
| 战斗 | 等级比较、奖励与负面状态 | 采用原判定 + 三波文字表现 |
| 随机强化 | 成长经历与主线 | 额外战技选择、最多1次进化 |
| 最终资格 | 实际等级+资源+主线 | **完全相同** |
| 玩家参与 | 策略、重要事件、援助、闭关 | 原有操作 + 可选战技选择 |
| 目标 | 安静观看多个分身各自经历 | 让清剿更有爽感，但不刷屏 |

## 当前原型切片

- \`index.html\`：手机竖屏入口。
- \`src/engine.js\`：确定种子、独立世界、自动行动、威胁、事件、成长、末日终局、记忆/援助/融合、实验战技选择。
- \`src/ui.js\`：首页、世界卡、策略、速度、暂停、事件、闭关、援助、战技、战报和结算。
- \`src/style.css\`：移动端文字卡片与进度条。
- \`idb-keyval\`：浏览器IndexedDB存档；存档与Profile分开。
- \`tests/engine.test.js\`：核心不变量与示例路径的单元测试。

**公开试玩前必须补足：** UI边界/自动暂停、行动点优化、技能效果真正参与战潮结算（目前主要是记录构筑和战报）、怪物/环境节奏、配置内容化与移动端真机测试。

## 游戏设计层面的高优先级风险

- 纯模拟当前自动救援效率较高，容易出现一味挂机仍连续双世界全救，末日压力与取舍不足。
- 新增战潮不能把战斗重新演变成单独的实时动作游戏，也不该靠大量弹窗堆“爽感”。
- 首局时长与第三局节奏必须通过实测，不能仅按20秒/日理论估算可玩性。

## 下一步

先保证原型稳定完成一整局、存档后继续，固化基础世界胜负和行动循环；再对比开启/关闭战潮模式的策略收益和操作量。数值/战斗体验属于核心问题，值得用正式可复现模拟后整体修改；实现细节尽量采用成熟工具。
