- `game-text.csv`：**499 个静态候选源码行、19 个文件**，包含首页文本、UI、世界成长、事件、三波战报、结局、彩蛋及部分英文标识。里面含代码、注释、非可见文本，因此 499 不等于游戏实际句子数。

- **新增 `npm run text:review`**：将上述两类候选放入一个 **UTF-8 BOM 的 `human-review-worklist.csv`**，按源码定位生成辅助指纹、分类及风险方向，并留空完整玩家实见原文、展示条件、人工决定、审核人和证据。
- 新 CSV 是在 CI 中生成并上传的工作底稿，不能当成官方要求的「全部文字」直接上交。审核者应下载后另存为 Excel 正式工作文件，**不要把人工结论写回会被自动覆盖的候选导出 CSV**。

## 人工审阅填表约定

1. 每行确认是否可见。仅当实测确认是内部变量/注释时，填「非玩家可见」，**不能直接删除不确定行**。
2. 在「玩家可见完整原文」填写可搜索的完整句子。对动态变量提供多组真实数值及分支；UI 中动态数值、战报、旧存档、失败路径都要涵盖。
3. 在「人工处理决定与理由」填写「保留/修改/待证据」，附复核人、日期、运行版本 SHA 和截图/录屏文件名。自动风险标签**不得作为通过结论**。
4. 若需要修改玩家可见文本，由专属改动 PR 协调 A/B 后实施；改字不改稳定事件 ID、数值、存档行为。刷新导出后逐条对照旧审核工作表，留存历史版本。
5. 当所有可见句式、分支和英文文本均可全文检索且经人工签署，才能制作最终无源码 Word/Excel；收到敏感深审通知时按官网 FAQ 9.11 送审。
