# B 第三阶段 · 玩家引导文案人工复核范围

来源：src/presentation/player-guidance.js。此文件仅生成展示数据，尚未在实际页面上渲染。

## 重点审阅

1. 世界观只强调分身、未知联系、救援和文明延续，不设定幕后反派或确定灾变真相。
2. 内部 P、D、AP 分别解释为救援准备、危机压力、干预点。界面建议优先中文名称；英文保留在内部变量中。
3. “危机100”“世界截止日”“灵魂强度耗尽”只有在结算日志确认时归入具体主因；其他缺口只是结束时状态，不是精确因果。
4. 含有“受伤”“巢群”“战斗”“兽王”等句式，需结合真实页面和相应动态变量复核。文本基调强调保护、撤离与救援。
5. 事件选项成功率仅透传现有引擎预览，并不生成新的概率或收益保证。规则调整后要同步复核。
6. 碎片目前只有数量记录，不要宣传为属性强化材料；纪念称号和隐藏收藏不提供战斗加成。
7. 如最终 UI 仅使用模块的部分文案，正式提交的审核文件仍应以可到达的真实游戏完整句子为准，包含旧存档日志。

## 导出与验证

提交/集成后依次运行 npm run text:export、npm run text:check、npm run text:runtime、npm run text:review。需要人工从动态候选中复原资源、费用、危险值、日期、世界名称等变量对应的真实句式；静态源码扫描文件不是 TapTap 完整可读的终稿。
