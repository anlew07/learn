# 战潮模拟实验包 01 · 幸存者式战斗 × 多世界模拟

**版本：概念原型 V0.1（2026-11-12） · 状态：【实验提案，尚未纳入核心架构冻结】 · 尚无游戏代码与平衡测试**

## 0. 为什么引入、哪些机制值得借鉴

希望给“自动成长、清剿、末日恶化”增加战斗滚雪球和构筑差异：自动攻击、敌潮压力逐渐增加、重要成长时提供少量随机强化选择、能力/经历组合进化、精英奖励和长局内的高光时刻。

**不复制**实时角色移动、捡取经验宝石、每秒碰撞、逐帧弹幕、10种以上主动武器或频繁升级弹窗。本游戏仍是 TapTap 竖屏文字 H5、多个世界共享一个游戏日、分身每天一个主要行动和三种长期策略。不要直接复制他人的角色、名称、武器美术与具体数值。

**策略定位：模拟约70% / 战潮与构筑约30%（仅作为设计比例，不是实测时长）**。模拟决定“何时何地为什么遇到尸潮/妖兽/兽群”；战潮系统负责“自动交战带来的战斗反馈与本局构筑组合”。

## 1. 分层：不让幸存者玩法吞掉模拟器

| 层 | 仍由谁决定 | 战潮如何介入 |
| --- | --- | --- |
| 世界演化 | GameEngine/ThreatSystem | 选择当前来袭类型、危险度、战潮警告 |
| 日常行动 | DecisionSystem 每世界每天一个主要行动 | 行动若是“清剿/狩猎”，可用三波战报描述其唯一结果 |
| 重大事件 | EventSystem | 使用同一个待处理事件实例呈现强化的战潮结果 |
| 终局 | FinaleSystem | 兽王/母巢胜负仍按既有资格与有效Lv；战潮可渲染，但不能篡改基础条件 |
| 跨世界 | SoulLinkSystem | 二人/三人之力只能作用于指定的合法战斗，不变为永久战力Buff |
| 局外成长 | ProfileState碎片与解锁 | 未来可以解锁额外的构筑候选池；**本实验不改永久数值** |

## 2. 战潮演出机制（WaveEncounter）

建议将已有“普通战斗/精英战/首领战”统一提供一个**可选**的三波战斗解释层。

- **普通日常战斗**：一次行动最多形成一次三波战报，消耗当天唯一主要行动；仍只领取原敌人/行动模板的一份奖励。
- **重大精英事件**：复用当前 eventInstanceId，展示“外围→聚集→首领”的三波结果。此事件按既有自动/玩家干预窗口结算，**不额外再生成三个重大事件或三日战斗**。
- **最终母巢守卫/兽王**：可使用三波文字演出，但严格先检查实际等级、P、材料、战斗要求，再支付费用并结算；P100不等于自动胜利。
- **灵灾条件型封印**：不强制插入任何Boss或战潮，避免改变已有普通封印规则。
- 三波是**同一次日结算内部的三个逻辑片段**，不额外推进全局时间、不暂停其它世界、不开实时位置系统。战斗结束后可以逐波显示记录，但结果在同一事务中一次性提交。

### 2.1 如何用数字表达“割草感”而不模拟500只怪？

不保存每只敌人、不建立角色血条；只保存本次遭遇的简化压力档位与临时结果。

| 字段 | 来源 | 作用 |
| --- | --- | --- |
| encounterId | 事件实例ID或当日行动唯一ID | 防重复 |
| waveCount | 当前演出模板 | 首版固定3，非三个真实每日行动 |
| wavePressureTier | 敌人模板+世界阶段+活跃威胁 | 决定战报压力描述和附加损失上限 |
| localClearBonus | 当局战技构筑 | 控制清潮效率、少量附加收益 |
| waveMitigation | 防护类战技 | 减少明确允许的战潮附加风险 |
| rewardSourceId | 原敌人/事件定义 | **唯一战利品来源** |
| bossCombatCheck | 旧有效战斗Lv公式 | 不由战潮表现层私自覆盖 |

**首版执行边界：** 保持当前“实际Lv+临时融合−受伤惩罚≥首领要求”的确定性胜负。三波主要用于视觉/文字表现、清潮效率与少量附带资源或D变化；**不因战潮评分而将原本必胜首领改为必败**。任何额外奖励必须在同一个事件的奖励预算内，不能重复发XP/R/P/D。

参考上限（候选）：每次战潮附加的资源不超过原奖励的25%；附加D减免不超过该次原定D减免的50%，并必须经过数值测试。全部属于【待测】而非正式公式。

## 3. 当局构筑：两个攻击位 + 一个辅助位

不是照搬6武器+6道具。每世界每局最多**两个攻击战技位、一个辅助战技位**，每个战技最多2级，最多触发1次进化；世界之间不能直接转移具体战技。

| 世界 | 攻击候选示例 | 辅助候选示例 | 组合进化示例 |
| --- | --- | --- | --- |
| 灵灾 | 驭雷符 / 飞剑回旋 | 聚灵阵纹 | 驭雷符 + 聚灵阵纹 → 雷阵连锁（提高清剿效率） |
| 尸潮 | 碎片飞刃 / 电弧投射器 | 简易护甲 | 碎片飞刃 + 简易护甲 → 钢雨防线（偏向减少遭遇损失） |
| 兽潮 | 裂爪连击 / 震地咆哮 | 追猎直觉 | 裂爪连击 + 追猎直觉 → 连环猎杀（偏向狩猎资源） |

**效果类型先限定三种：** `waveClearBonus`（清潮效率）、`waveLossMitigation`（减少战潮相关损失）、`waveLootModifier`（额外资源但受奖励预算上限限制）。不新增攻击速度、暴击、吸血、击退、体力、投射物数量等八种独立属性。

- 每个构筑的标记是本世界本局的 `combatBuild`，不替代世界成长等级。
- 进化只改变对应的局内战潮效果和战报表现；不自动修改BOSS的战斗要求、P里程碑或灵魂融合费用。
- 进化需“已有两个指定组合项 + 合法强化机会”；**不会**因为读档或重复战报自动进化第二次。
- 数值有上限：即便有多个战技，首版 `waveClearBonus` 最多+1档，附带奖励预算仍独立封顶。

## 4. 强化选择：少量三选一，挂机也能自动处理

不在每次XP增长或实际Lv提升时不断弹窗。用一个独立于重大事件槽的 `pendingBuildChoice` 结构，来自明确且稀疏的成长里程碑。

**候选生成时机（设计候选）：**

1. 本世界首次达到实际Lv2。
2. 本世界首次进入P≥65阶段。
3. 本世界第一次击败精英，前两次选择已完成后可触发（若从未遇到精英，则不强制出现第3次）。

每世界**最多产生3次构筑选择**；同一时间最多1个待选，下一候选因已有待选而忽略或最多排队1条，不能无限积累。生成时固定随机流抽取合法候选，**3选1、且同一次选择不重复候选ID**；已有战技可升级，空位可获得新战技，满槽时只出现升级/可合法进化的选项，至少一项为可执行保底。

### 4.1 玩家操作与自动选择

- 三选一**不消耗AP和灵魂强度**，因为这属于分身自己的局内成长；如果要重抽选项、手动跨世界强行替换才考虑未来成本，首版不做。
- 强化机会按世界策略自动预选：成长优先偏发育，清剿优先偏群攻，拯救优先偏稳健；评分相同时按固定种子与稳定ID排序。
- 玩家可打开世界详情主动覆盖本次构筑选择；选择面板可自愿暂停计时；**不会因为没有点击而卡住多个世界**。
- 待选最迟两完整游戏日内按自动预选结算，不占重大事件槽、不阻止日常挂机；过期与手动选择只能提交其中一种结果，世界saved/failed则直接取消未完成选择。
- 实验默认设置“自动构筑开启”，玩家可切换“关键强化提醒”而不是每个升级都弹出全屏界面。

**时间取舍：** 三世界时最多9次构筑机会/整局；实际上许多世界可能只触发前两次。需在试玩中检查是否比多世界事件干预更频繁；若影响局长，减至每世界2次或完全自动。

## 5. 三世界状态与“幸存者感”的关系

- 灵灾：妖兽巢穴形成一场“群妖围山”；群攻可减少清剿相关损失，但闭关仍会让妖兽压力继续增加。
- 尸潮：停车场尸群形成一场“感染者围城”；某些组合可让分身更稳定清巢，**不能把材料预留和防线修复取舍抹掉**。
- 兽潮：赤角兽群形成“迁徙冲击”；狩猎类构筑增加有限战利品，**不能消除兽王随时间进化，也不能绕过Lv4独立终战压制路线**。

所有三波事件对玩家的关键提示仍为：行动/事件来源、自动战斗结果、清潮贡献、获得资源、D变化、是否新获得构筑选择。没有掉满地的宝石、没有额外的战潮倒计时。

## 6. 与万我同源的接口

- 记忆共享候选由**重大突破/精英首胜**产生，普通三波战报和波内大量击杀**不重复产生记忆共享**。
- 二人/三人之力仍只对指定重大/终局战斗提供+1/+2，且需要符合世界与AP/魂状态；与本地一次性战斗强化**互斥**。
- 当前战潮构筑只影响战潮附加收益与减损，不影响融合资格和实际等级；来源的“灵魂分流”虚弱从下一全局日开始衰减可缩放XP/R收益。
- 已结束世界停止构筑、战潮、普通借力；已获得的世界回响沿原本一次性规则处理。

## 7. 可开关的设计实验，而非已确定的核心规则

建议在设计基线之外设置 `survivorWaveExperimentEnabled`（未来实现时属于规则配置，而非额外玩家数值条）。

- **关闭**：完全沿用当前自动战斗、敌人模板、事件、结局和奖励。
- **开启**：对配置为 `wavesEnabled` 的战斗生成三波战报与局内构筑，且只允许在原结果预算内出现小幅修正；其余事件和世界逻辑不变。
- 两种模式应该能通过相同规则版本/固定种子进行A/B比较；保存实验开关与构筑、强化候选实例和随机流，避免恢复存档时模式漂移。
- 这不是线上随意切换一个已开局的实验模式；每一局开局固定配置。早期测试存档可以明确提示重开，不承担未发布版本的迁移承诺。

## 8. 验收用例（尚未执行）

1. 不开启战潮实验：同种子/同操作保持旧规则结果。
2. 开启后普通狩猎的一次主要行动可以形成三波演出，但不能产生三次XP或额外三天时间。
3. 已生成的停车场精英事件不会因为三波演出重复生成三个待选重大事件。
4. 三世界各自独立自动战斗，打开一个世界战报不会冻结其它世界的逻辑结算。
5. 实际Lv2时每世界最多生成一次指定构筑候选；刷新不重抽。
6. 同一次三选一不能出现两个同ID候选。
7. 玩家未手动选择时，在期限届满时按策略自动结算；不会让局内推进卡死。
8. 玩家已选择则到期不再自动选择；一次构筑升级最多生效一次。
9. 两攻一辅满槽时，候选池只提供合法升级/进化或保底，不出现无法装备项。
10. 组合进化必须满足两个指定组件和一次合法强化机会；不能只靠读档反复进化。
11. 战潮加成不得提升实际Lv，不得让未达母巢/兽王基础资格的分身直接通关。
12. 战潮对Boss胜负不改变旧战力对比；只允许经预算审查的清潮收益/损失修正。
13. 多波击杀不广播多份记忆；首次精英首胜仍按原共享限制正常广播一次。
14. 活跃巢穴已经 cleared，则下一个环境阶段不再施加它的额外D。
15. 一个战潮事件被手动融合后，融合AP/魂与本地强化不会重复叠加或重复扣费。
16. 兽潮Lv4、兽王狂化Lv5、无随机机缘和不融合：原有两次压制路线仍可独立救下世界。
17. saved/failed 世界不能再收到构筑、事件或战潮战利品；构筑待选直接取消。
18. UI在1×/4×下可看懂三波战报且不用持续点击；若弹窗时间明显偏多须减少构筑选择频率。
19. 离线不推进，读档恢复相同本局构筑、候选ID、战潮/事件实例与随机流。
20. 以固定种子对比实验开关：统计世界获救率、决策次数、平均日数、每局战报长度、构筑多样性、玩家干预频率，避免只用“爽感”判断。

## 9. 采用门槛与后续

**建议**：先设计并在未来编程后做一次“尸潮停车场精英战潮”竖向切片；再移植灵灾狼巢、兽潮赤角巢群。若A/B证明战潮显著增加操作负担或打破多世界自动模拟，保留自动三波战报、删除手动构筑即可，不需要重写世界引擎。
